## 0. 가장 중요한 10가지

1. **엔진마다 병목이 다르다.**
   - [순정]: 블록 하나 0.3~2 µs이고, 해석기가 시간 대부분을 씁니다. **블록 수를 줄이는 것이 전부입니다**(OBJ설, OB:42, PH:43).
   - [tess]: 블록 비용은 수 ns로 싸서 그리기(채우기 수)와 소수 계산이 병목입니다(RH:1375-1378, RH:1334).
2. **소수 계산이 비싸다.**
   - 엔트리 `+ − ×`는 십진 BigNumber 흉내입니다. [tess]에서 정수끼리는 약 3 ns이지만 비슷한 소수끼리 빼면 130–250 ns입니다.
   - 처방: **cm·×16384 정수 고정소수점으로 곱하고 더한 뒤 마지막에 한 번 나누기**(RH:1334-1338, RI:73-74).
3. **반복의 딜레이를 없앤다.** 반복 블록은 한 바퀴마다 한 프레임 쉽니다. `<이번 반복 건너뛰기>가 아니다 이(가) 될 때까지 기다리기`를 넣으면 한 프레임 안에서 쉬지 않고 돕니다(GD:130, 기술 §1, RH:1340).
4. **값 함수의 본문이 비면 호출마다 1~2프레임(33 ms)이 걸린다.** 문장 하나(지역 변수 정하기, `만약 <거짓>`)를 넣습니다. 값 함수를 문장 자리에 두면 작품이 열리지 않습니다(EX:21, GH:38, VL).
5. **리스트는 5000칸이 한도다.** 쪼개기, 페이징, 한 칸에 여러 값 묶기, 문자열에 담기로 대응합니다(RH:1535-1542, GH:8-10, RT:126-135).
6. **저장 한도는 프로젝트 문서 약 16 MB다.** 기준은 `Entry.exportProject()` 크기이고, 파일 크기가 아닙니다. 줄이는 방법은 다음과 같습니다(SM:129-134, RH:902-910, BH:190-205).
   - 0만 든 리스트는 비워서 저장하고 시작할 때 채웁니다.
   - 큰 리스트는 문자열로 압축합니다.
   - 펼친 매크로는 함수로 바꿉니다.
7. **정렬 없는 화가 알고리즘을 쓴다.** 트랙 순서 + 삽입 정렬, 버킷 사슬, BSP, 맨해튼 거리 순서, 8방향 미리 정렬 중에서 고릅니다.
8. **[tess] 같은 색 묶음으로 그린다.**
   - 같은 스타일의 2점 획이 16개 넘게 이어지면 한 메시로 묶입니다. 색별로 모으면 15 → 1.3 ms입니다(RT:27).
   - 반투명 채우기는 색·투명도 묶음마다 텍스처를 하나씩 만듭니다. 고스트 하나로 8 fps까지 떨어졌습니다(RH:8-25).
9. **무작위 수 블록은 경계에 소수가 있으면 `toFixed(2)`로 반올림한다.** `rand(0.0001,0.9999)`는 0.5% 확률로 0이 됩니다. 대신 `rand(0,999999)/1000000`을 씁니다(RH:544-548).
10. **측정은 같은 실행 안에서 A/B를 번갈아 3회 이상 한다.** 순정·소프트웨어 GL·CPU 스로틀은 회차마다 ±15%~2배 흔들립니다(RH:24, RH:615, PH:43).

### 측정 규칙과 함정
**A/B 방법**
- 빌드를 번갈아 3회 돌리고 race2–4 tick 평균을 씁니다. 한 빌드의 첫 회는 자주 튑니다(RH:717).
- 세 번 모두 같은 방향이면 1~2% 차이도 실제로 봅니다(RH:576).

**흔들림**
- CPU ×4 스로틀은 같은 빌드끼리도 ±15% 흔들립니다(RH:615).
- 보통 속도에서는 60 fps 상한에 막혀 차이가 안 보입니다.
- 스로틀은 측정 구간에만 걸면 한 번에 3분 걸리던 것이 1분이 됩니다(RH:630-632).
- 소프트웨어 GL은 회차마다 ±5 fps입니다. 같은 실행 안의 기준값(예: "고스트 없음")과 비교합니다(RH:24).
- [순정]은 같은 PC에서도 잴 때마다 최대 2배 다릅니다(PH:43).
- 크롬 창이 여러 개 떠 있으면 처리량이 절반이 됩니다(SM:219-238).

**순정 편집기에서 µs 측정**
- 한 프레임이 몇 초가 되면 페이지가 죽으므로 측정 사이에 `wait_second(0)`를 둡니다.
- 블록 수천 개짜리 스크립트도 편집기를 죽입니다. 라운드는 반복 블록으로 돌립니다.
- 첫 라운드는 JIT 때문에 느립니다. **라운드 최솟값**을 씁니다(EX:23).
- exp는 "200값 × 5번 × 14라운드 중 최솟값"으로 쟀습니다(exp설 "측정 방법").

**타이머와 환경**
- [순정] 초시계는 프레임 사이에만 갱신됩니다. 측정 앞뒤로 한 프레임씩 기다립니다(약 +0.03 s)(GD:120-127, GH:54).
- 헤드리스 크롬은 약 25초 뒤 틱이 2배 느려질 때가 있습니다. 창을 띄우면 없습니다.
- 크롬 154는 Node 24보다 약 25% 느립니다(RT:32; RT설 "한계").

**시뮬레이터 함정**
- sim을 10 fps로 돌리면 프레임당 확률 버그가 60 fps 실게임보다 6배 약하게 보입니다(RH:575).
- 컴파일러가 블록 id에 `Math.random`을 씁니다. 같은 경주를 재현하려면 sim을 만든 **뒤** 경주 직전에 다시 시드합니다(RH:98, 635).
- LCG를 double로 돌리면 값이 반복되어 멈췄습니다. mulberry32로 바꿨습니다(RH:636).
- `Math.random`을 0으로 고정했으면 새 sim을 만들기 전에 되돌립니다. 안 그러면 시작 중 무작위 반복이 끝나지 않습니다(RH:95).

**하네스 함정**
- 0.5초마다 `page.evaluate`로 변수를 읽어도 멈칫의 원인은 아니었습니다(RH:32).
- tessvm 하네스의 `press`는 한 틱 안에 끝나 키가 안 잡힙니다. `down`/`wait`/`up`을 씁니다(GH:55).
- 하네스는 작품을 하나만 올립니다. 시험을 동시에 둘 돌리지 않습니다(BH:266-270).
- 한 Node 프로세스에서 편집기를 약 10회 재부팅하면 키 이벤트가 오지 않습니다. 시나리오마다 자식 프로세스로 격리합니다(VL).

**tessvm 수치 읽기**
- 틱 29 ms면 `ticks/s`는 34로 나오지만 화면은 초당 9번만 그려집니다. 틱 수만 보면 속습니다(RT:26).

## 3. 수 계산

### 정수 고정소수점 [tess 중심]
**표준 단위**(RH:1337-1338; 기술 §2; BD §1)

| 대상 | 단위 |
|---|---|
| 월드 좌표 | cm 정수(`WU`) |
| 카메라 축·회전 | ×16384(`BS`) |
| 뷰 깊이 | 1/ZU m |
| 화면 좌표 | 1/16 px(`QS`) |
| 차 모델 | mm 정수 |
| 차 법선 | ×1024 |
| 면 평면 오프셋 | mm×1024 |

- 모델 → 뷰 변환은 물체마다 정수 행렬 하나로 합칩니다(정점당 곱 9번).

**결과**: 싱가포르 ULTRA 13–21 → 5–6 ms/틱. 순정도 1.9 → 2.55 fps가 됐습니다(RH:1339, 1348).

**주범은 "짧은 소수"보다 상쇄 뺄셈이다**(RH:732-733; RI:8)
- 비슷한 두 소수의 차를 구하는 계산입니다(차 위치 − 링 위치 등).
- 소수 꼬리를 길게 해도(`longTail`, LONGK) 뺄셈은 그대로 느립니다. **정수화만이 해법입니다.**
- 정수끼리는 `Number.isInteger` 뒤 바로 반환됩니다.

**단계별 효과**(레이싱)

| 판 | 한 것 | 결과 | 출처 |
|---|---|---|---|
| v5.1 | 가장자리 선·컬링·풍경 판정 정수화 | 틱 약 −4% (모나코 5.51 → 5.32 ms) | RH:734-738 |
| v5.2 | `sampleTrack` 링 탐색과 차 사이 거리를 cm 정수로(`carsCm()`), 0 곱하기 건너뛰기 | 멜버른 4.24 → 3.97 ms, toFixed 3057 → 2377/프레임 | RH:708-715 |
| v6.1 | 프레임 상수를 setupCam으로, drawScn 시야 판정 정수(×65536), `pvZ` 정수 깊이, 하늘·산 정수 + 로딩 때 표 | CPU×4에서 −7~−10% | RH:637-653; RI:147-159 |

- v6.1 단계별 기여: 9(시야 판정) > 하늘·산 ≈ 10(정수 깊이) > 8(상수 이동)(RH:653).

**정밀도 함정**
- 정수 스케일이 거칠면 오차가 납니다. 거울 법선을 ×1024로 했더니 스치는 반사가 0.5% 어긋나 ×16384로 바꿨습니다(RT:97).
- 정수 비교 값이 2^53 안에 드는지 확인합니다(약 2e12면 안전)(RI:103).
- 엔트리 숫자는 2^53(약 9×10^15)을 넘으면 정확도가 깨집니다(GD:3).
- GMP limb는 10^7진입니다. 곱이 10^14 < 2^53이고, 그런 곱을 80개 더해도 넘치지 않습니다(GD:76).

**긴 꼬리 상수**
- 상수 `0.50000000003141593`은 `String`이 15자리(`0.500000000031416`)로 잘라 꼬리가 짧아졌습니다. `String(c)`의 소수 자릿수가 16 이상인지 확인합니다(RH:713-714).

### [순정] 사칙연산을 피하는 블록 트릭 (exp)
- **몫·나머지는 BigNumber를 거치지 않습니다.** 곱하기·빼기 대용으로 씁니다. x = n·ln10 + r을 몫·나머지로 얻습니다(EX:19; exp설).
- **`합치기(합치기(m,"e"),n)` = m×10^n**(곱셈 0개). 숫자를 받는 블록이면 어디서나 됩니다. 단 m이 지수 표기(1e-7 이하, 1e21 이상)면 안 됩니다(EX:20).
- 칸 번호 반올림은 `round(합치기(j,".5"))`로 덧셈 없이 합니다. 음수 j에는 나머지를 구한 뒤 씁니다(EX:42).
- `10^(j/256)`은 `"1e"+j`에 루트를 8번 하면 됩니다(리스트 없는 표)(exp설).
- 결과: 원본 15개 사칙연산 → 4개. 함수 몸통 39.3 → 21 µs(약 1.9배)(EX:26-29; README).
- **옛 사칙연산 블록**(`calc_plus/minus/times/divide`)은 BigNumber 없이 그냥 `a+b`입니다(OB:39).
  - [순정] 꼭짓점 변환 43 → 31 µs, 매듭 한 장 122 → 108 ms.
  - [tess]는 같은 코드로 컴파일해서 손해가 없습니다.
  - 블록 꾸러미에는 없는 블록이라, 엔트리가 없애면 `LEGACY=0`으로 다시 빌드합니다.

### [tess] 나눗셈은 싸다
- `divNum`은 결과 절댓값이 0.001 미만일 때만 느린 길로 갑니다. **정수로 곱하고 더한 뒤 마지막에 한 번 나누기**가 기본 처방입니다(RI:73-74).
- 나눗셈·제곱근은 `idiv`, `idiv(sqrt,1)`로 바로 정수로 만듭니다(RT:29).

### 숫자 상수는 글자다 [tess]
- 블록 안의 숫자 `5`는 `"5"`로 컴파일되어 쓸 때마다 `parseFloat`합니다.
- 함수 진입 때 `(5-0)`으로 만든 지역 변수에서 읽게 하면 틱이 23 → 19 ms가 됐습니다(RT:28).
- 효과는 함수 성격에 따라 엇갈립니다. 17절 표를 보세요.
- TinyStories 행 커널에서는 숫자 리터럴이 전체 블록의 19%였습니다(다음 최적화 후보)(SM:241).

### 나눗셈 정밀도·지수 표기 [둘]
- **나눗셈은 소수 20자리에서 잘립니다**(BigNumber DECIMAL_PLACES 20, tess도 흉내). `1/e^50`은 0이 됩니다.
  - 대응: 몫이 0.001보다 작으면 분자에 10^25(더 작으면 10^150)를 곱해 나눈 뒤 되돌립니다(CP:27, 52; 그래퍼설).
- **PLUS에 지수 표기 숫자를 넣으면 글자 이어 붙이기가 됩니다**(`x + 1e-25`). 곱셈·뺄셈·비교는 괜찮습니다(CP:31; SM:75).
  - 레이트레이서는 `x+3`을 `x-(-3)`으로 썼습니다(RT:28).
  - 그러나 `a+b` → `a-(0-b)`(FASTPLUS)는 더 느렸습니다(RT:31).
- 1e21을 넘으면 숫자가 `1e+21` 꼴 글자가 됩니다(exp설).
- BigNumber(double)는 그 수의 가장 짧은 십진 표기로 계산합니다. 큰 x를 십진 뺄셈으로 줄이면 반 ulp가 그대로 오차가 됩니다. 정밀판은 나머지 블록(이진)으로 줄였습니다(EX:24).
- `소수점 부분` 블록은 음수에서 |n|의 소수 부분을 줍니다. `나머지(n,1)`을 씁니다(EX:37).

### 계산 구조
- **0 곱하기를 건너뜁니다**(직선에서 aiPlan 가중치, DRS·tow·ERS가 0인 항)(RH:712).
- 한 프레임 동안 변하지 않는 값(LOD 거리², 하늘 띠 색, 회전계 좌표)은 setupCam이나 로드 때 한 번만 계산합니다(RH:638; RI:95-99).
- 카메라·태양을 **물체 로컬 좌표로** 옮깁니다(RH:1389).
  - 면마다 뒷면 판정과 밝기 계산이 내적 하나로 끝납니다.
  - 1.0M → 0.73M 블록/프레임.
- 표 방식은 이득이 작습니다(EX:38-39; exp설).
  - 리스트 읽기는 0.47 µs지만 칸 번호 계산과 곱하기까지 표 하나에 약 4 µs입니다.
  - 4096칸 표로도 11%만 빨라졌고, 얻은 것은 주로 정확도입니다.
  - 표를 둘·셋으로 늘리면 손해입니다.
- `atan2` 대체: `2·atan(y/(|f|+x))`. 블록 하나이고 사분면 분기가 없습니다(그래퍼설).

## 4. 반복·딜레이·프레임

**반복의 양보**
- [순정] 반복 블록은 한 바퀴마다 화면을 갱신하며 쉽니다.
  - 조건 자리에 `계속 반복하기` 계열 또는 `<이번 반복 건너뛰기>가 아니다 이(가) 될 때까지 기다리기`를 넣으면 한 프레임 안에서 쉬지 않고 돕니다.
  - 그동안 화면은 멈춥니다(GD:130; 기술 §1).
- [tess]도 `wait_until_true(not continue)` 트릭을 무양보 루프로 인식합니다(RH:1340).
- `for(;;)`는 매 반복 양보합니다. 함수 안에서는 `while(true)`를 씁니다(SM:79; GH:28).
- `repeat N`은 "한 바퀴 = 1프레임 양보"라서 빠른 이벤트 재발화와 겹쳐 전역 카운터가 범위를 넘었습니다. 동기 재귀 값 함수로 옮기면 원자적입니다(VL).

**재귀 vs while** [tess]
- 모든 `while`을 자기 호출 함수로 바꾼 v1.alpha는 틱 27~31 ms였습니다. while판(13~14 ms)의 약 2배입니다(RT:62).
- 변수 배치가 중요했습니다. 전부 전역이면 44 ms였습니다. 반복과 바깥이 같이 쓰는 변수는 전역으로, "읽기 전에 반드시 쓰는" 변수는 반복 함수의 지역으로 둡니다(RT:62).
- 초기화 재귀 4만 단계는 JS 스택을 넘겨 Node 시뮬레이터로 돌릴 수 없었습니다(RT:63).
- **결론: 재귀가 아니라 딜레이 없는 while을 씁니다.**

**[tess] 틱 모델**
- 틱은 1/60초로 고정입니다. 틱이 16.7 ms를 넘으면 한 화면에 틱을 최대 4개 몰아 실행합니다(`maxCatchUp 4`)(RH:1332; RT:26; BD §1).
- **타이머도 틱 기반입니다.** 60 fps가 안 나오면 게임 전체가 슬로모션이 됩니다.
  - 대응: `get_date SECOND`(현재 초)로 실제 초당 틱을 세어 dt 배율 `rtK`를 정합니다(RH:1333; 그래퍼설 "시계").
- 두 엔진에서 실제 시간으로 가는 시계는 "현재 초"뿐입니다(그래퍼설).

**[순정] 프레임 시계**
- 프로젝트 타이머는 60 Hz setInterval로 갱신되어, 긴 프레임 동안 굶거나 0과 2배 값이 번갈아 나옵니다.
- dt를 지수이동평균으로 다듬고 실제 시계 쪽으로 천천히 당깁니다(RH:1425; E3:79-80).

**물리 서브스텝**
- 물리·조작을 55 ms 이하 조각으로 나눕니다. 없으면 저프레임에서 AI가 12 m를 눈감고 달립니다(RH:1628-1630).
- 프레임 델타 상한은 0.09 → 0.18 → 0.30 s, 서브스텝 상한은 4 → 6으로 올렸습니다(RH:1565).
- 이동 거리 기준 서브스텝(BR)
  - 한 번에 30 cm 넘게 움직이면 16 cm씩 나눕니다(계단 끼임 방지)(BH:15; BR설).
  - 연체는 2 cm, 강체는 1 cm 걸음입니다(빠른 쇠공 관통 방지)(PH:32).
- 비싼 판단은 프레임당 1회, 조작은 서브스텝마다 합니다(`aiPlan` / `aiDrive`)(RH:1630).
- 프레임 의존 감쇠 버그: 벽 접촉 물리 스텝마다 ×0.84를 곱했더니 60 fps에서 0.5° 스침이 1초 만에 216 → 6 km/h가 됐습니다. 감쇠는 `dt`에 비례하게 씁니다(RH:1061-1064).
- 공중 판정에 dt를 넣지 않으면 프레임이 낮을수록 내리막에서 뜹니다(RH:556-557).

**부하 분산**
- 타이어 계산은 0.1초 틱마다 하고, 차마다 시작을 엇갈립니다(RH:1031).
- 갱신 주기를 낮춰 3~5% 정도를 얻을 수 있습니다(제안, 미적용)(RI:43-46).
  - 먼 AI `aiPlan`은 2프레임마다.
  - 슬립스트림은 3프레임마다.
  - 미니맵은 2프레임마다.
- AI 2단계(BD §6)
  - 가까운 12명은 FULL(지각 5 Hz, 결정 2 Hz, 엇갈림).
  - 나머지는 프레임마다 2명씩 요약 시뮬레이션.
  - 흐름장은 프레임당 노드 200개, A*는 400노드 상한.
- 정해진 시간만 흐르게 하기(물리)
  - 한 장 = 1/30초 시뮬레이션 시간으로 정합니다. 순정에서 한 장에 몇 초가 걸려도 결과가 같습니다(물리설).
  - 잡기 목표점 속도는 시뮬레이션 시간 기준으로 제한합니다(1.5 m/s). 안 그러면 159 J로 휘둘렸습니다(PH:34).

**입력**
- 키·클릭은 이벤트로 받습니다. 프레임마다 `key()`/`mouseDown()`을 보면 두 프레임 사이에 눌렀다 뗀 입력을 놓칩니다. k틱마다 그리는 저속 모드에서 특히 그렇습니다(BH:305-307).
- 이벤트 스크립트와 메인 루프 중 어느 쪽이 먼저 도는지는 정해져 있지 않습니다(BH:308).
- [tess] `$DELTA_X/Y`는 틱마다 새로 쓰입니다. 그리기를 건너뛰는 틱에도 매 틱 더해 모읍니다(BH:315).
- `ask`(묻고 기다리기) 동안 메인 루프가 멈춥니다. 끝나면 프레임 시계를 초기화합니다(RH:1286).

## 5. 함수

**값 함수의 지연**
- [순정] 문장이 하나도 없는 값 함수는 호출마다 프레임을 넘깁니다.
  - EX는 2프레임(33 ms), GMP는 1프레임이라고 적었습니다.
  - 지역 변수 정하기 하나나 `만약 <거짓>` 하나를 넣으면 µs 단위가 됩니다(EX:21; GH:38; GD:120-127).
  - 17절 모순표를 보세요.
- 값 함수 호출을 문장 자리에 두면 `.ent`가 열리지 않거나(`appendChild … not of type 'Node'`, 에러 단서 없음) 그 블록이 실행되지 않습니다. 반환값을 sink 변수에 담습니다(VL; GD:120-127; BH:316-320).

**함수 구조**
- 함수 중간 `return`은 불가능합니다. `vis` 같은 플래그로 감쌉니다(RH:1363, 1657).
- ejs는 매개변수 재대입을 못 합니다(RH:1363).
- [tess] 지역 변수가 많은 큰 함수는 진입만으로 비쌉니다.
  - `traceCluster`(구간마다 호출)를 `traceRow`(줄마다 한 번)로 바꾸니 진입 비용이 자체 시간의 47%였던 것이 없어져 틱 15.1 → 13.3 ms(−12%)(RT v1.3).
  - 드문 경로를 함수로 빼도(`mirrorCell`) 호출 비용과 비슷해 이득이 없었습니다(RT:31).

**펼치기 vs 함수**
- 속도: 매크로로 펼치면 호출 비용은 없지만 블록 수(=저장 크기)가 늘어납니다.
- 크기: 차가운 코드의 매크로를 함수로 바꿉니다.
  - BR `M_pface` 6번 펼침 → 함수로 바꿔 −1900블록. 1/4 배속 틱은 8.7–14 ms로 그대로였습니다(BH:106-109).
  - v1.2에서 매크로 11개를 함수로 바꿨습니다(BH:140-144).
  - SmolLM KV 그룹별 복제 함수를 하나로 합치고 `substr`로 구간을 넘겨 project.json 16.09 → 15.13 MB, 런타임 비용은 무시할 수준(SM:210-213).

**파라미터 타일**(GMP) [순정]
- 함수 파라미터 읽기는 O(1)이지만 `S[i+3]` 리스트 읽기는 블록 4개입니다.
- 16×16 곱을 통째로 펼친 함수(파라미터 33개)에 피연산자를 파라미터로 넘깁니다. 곱 하나에 블록 약 5.5개로, 이중 반복 대비 2.3배 빠릅니다(GD:92-94).
- 64×64 곱 기준

  | 방식 | µs |
  |---|---|
  | 이중 반복 | 11.2 |
  | 행 4배 펼침 | 8.9 |
  | Comba 8배 펼침 | 7.3 |

## 6. 변수·리스트

### 5000칸 한도
**엔트리의 동작**(2026-09-21판 entryjs, `LIST_MAX_LENGTH=5000`)(GH:8-10; GMP설 §3)
- push·insert로 넘기면 `slice(-5000)`으로 **맨 앞 칸이 지워지고** 경고 토스트가 뜹니다.
- 작품을 열 때도 뒤쪽 5000칸만 남습니다.
- 칸 바꾸기는 한도와 상관없지만, 없는 칸은 바꿀 수 없습니다(오류).
- BR은 "넘는 push는 무시"되고 "can not insert value to array"가 났다고 적었습니다(BH:202). 17절을 보세요.
- [tess]에는 한도가 없습니다. 그래서 tessvm에서만 시험하면 놓칩니다(BH:202; GH:10; RT:126).

**대응**
- **빌드와 시뮬레이터가 5000 초과를 검사해 에러로 멈추게** 합니다(RH:1536; RT:135; E3:46-49; GH:42).
- 쪼개기
  - 레이싱 `colTab` 8448칸 → 하늘별 2816칸 리스트 3개. 로드 때 현재 것을 복사합니다. 인덱스에서 트랙 베이스가 빠져 핫 패스도 싸졌습니다(RH:1537-1540).
  - 레이트레이서 40000칸 × 4 → 5000칸 저장소 A/B. 비용 12.0 → 12.5 ms(RT:126-135).
- 페이징(GMP): `M[i]`를 `M__get`(1번 리스트를 먼저 보고 나머지는 반씩 나누는 `만약` 나무)으로 컴파일합니다(GD:81; GH:12-14).
  - 5000칸 × 32개.
  - 핫 루프는 연속 구간을 작업 리스트로 통째로 옮겨(1024씩) 계산합니다.
  - 비용은 10% 안쪽입니다(π 700자리 0.90 → 0.97 s).
- 한 칸에 여러 값 묶기
  - 그림자 지도 8칸 → 3진수 한 숫자(16384 → 2048)(RT:126-135).
  - 리플레이 진행도·오프셋 → `round(p·100)·1000 + round((off+50)·10)`(RH:112).
  - 색 RGB → `r*65536+g*256+b`(E3:35-40).
  - 회전별 밝기 3비트 × 4 → 한 수. `mod(idiv(CR[f], RK8[iR+1]), 8)`로 꺼냅니다(BH:204).
  - GMP는 한 칸 여러 자리를 버렸습니다. 숫자로는 2자리만 정확하고, 문자열로 이으면 자르고 붙이기 때문에 곱셈이 아주 느려집니다(GD:80).
- 버퍼 하나에 몰아 담기: 링 461 × 10점 + 차 272 + 계산용 → 4938/5000. `NSEG` 상한은 이 식으로 정해집니다(RH:1392, 1541).
- 오브젝트 수 한도로 바꾸기(엔진 v5): 오브젝트·점·면 4900, 모양 200, 바디 1200. 넘으면 이유를 변수에 적습니다(E3:46-49; v5설).

### 리스트·변수 찾기는 선형 [순정]
- 리스트를 쓸 때마다 전체 리스트 목록을 앞에서부터 찾습니다(`_.find(lists_,{id_})`). 리스트 하나 지날 때 약 8 ns, 300번째는 +2.4 µs입니다(OB:40).
- **뜨거운 리스트·변수를 목록 맨 앞에 둡니다**(빌드의 `listOrder`/HOT 정렬)(OB:40; SM:72; 기술 §1; E3:56).
  - SmolLM: 표 리스트 뒤에 리스트 200개가 있으면 조회당 +3 µs.
  - 리스트 순서는 런타임에 바꿀 수 없습니다. 페이징한 뒤쪽 리스트는 느립니다(OB:68).

### 리스트 운용
- **줄이지 말고 덮어씁니다.** 시작할 때 다 만들어 두고(push 0회) `A[i]=v`만 씁니다(BD §2.4; PH:13; OB:32).
  - 쓰레기와 길이 불일치를 막습니다.
  - 리스트를 줄이지 않으면 끝에 지난 값이 남습니다. 길이는 `.length` 대신 별도 변수(`N_`)로 관리합니다(BH:30).
  - 초기화는 길이를 줄이지 않고 카운터만 0으로 돌립니다(E3:28-34).
- 버전 도장으로 지우기 생략: 쪽이 바뀔 때마다 도장 값을 8192씩 키우면 지난 값이 저절로 무효가 됩니다(OB:30-34).
- 리스트 0번 칸은 0으로 읽힙니다. 삼각형의 넷째 꼭짓점을 0으로 두면 모델 원점이 넷째 점이 되어 띠로 늘어납니다. 셋째 점을 되풀이합니다(BH:309).
- 리스트 범위 밖 읽기는 스레드를 조용히 멈춥니다. `&&`·`||`는 단락 평가를 하지 않으므로 겹친 `if`로 보호합니다(기술 §1; VL).
- 아직 채워지지 않은 리스트를 다른 오브젝트가 먼저 읽으면 "can not insert value to array"로 죽습니다. HUD 오브젝트가 게임보다 먼저 돌았습니다. `length >= n` 가드를 둡니다(E3:81-83).
- 비트 플래그 리스트는 통째로 대입하지 않습니다(다른 비트가 지워짐). 세터를 씁니다(E3:90-91).
- 리스트 인덱스 0/1 기준을 빌드와 런타임에서 맞춥니다. `mVS/mFS`를 1부터 구워 모든 모양이 한 칸씩 밀린 일이 있었습니다(E3:73).
- sim의 `peek`는 리스트를 0부터 셉니다(`caThr[0]`이 1번 차). 테스트를 쓰다 두 번 틀렸습니다(RH:1209, 1295).

### 공간 자료구조
- 공간 해시 격자를 씁니다(E3:41-45; v5설).
  - 그리기용: 셀 20, 512버킷.

## 7. 문자열

**합치기·길이로 덧셈 대신하기**(SmolLM) [순정]
- `합치기`는 약 0.2 µs이고 V8 로프라 길이와 무관하게 O(1)입니다. `길이`도 O(1)입니다.
- 곱셈 결과를 길이가 그 값인 문자열(5 → `IIIII`)로 표에 만들어 두고, 이어 붙인 뒤 길이를 잽니다. `+`(약 2 µs) 없이 행렬곱을 합니다(SM:10, 69-70).
- 단항 문자열은 한 단계(±2499)일 때 1% 오차였고, 2단 단항(`UH[v div 4096] ⊕ U[v mod 4096]`)으로 1e-5가 됐습니다. 로프 최대 4.48억 < V8 한도 5.36억(SM:64-66).

**큰 데이터는 문자열 하나에**
- `substr`은 V8 SlicedString이라 O(1)입니다(SM:50-54).
- 가중치 3개(3·3·2비트)를 Latin-1 한 글자에 담습니다(평균 2.67비트). 행렬 하나가 문자열 하나라서, 5000칸 리스트에 1억 개를 넣었습니다(SmolLM설).
- `indexOf` 한 번으로 문자 → 리스트 인덱스를 얻습니다(패딩 + 알파벳 문자열)(SM:61).

**레코드 문자열**
- 풍경 물체 = 64진 21글자, 서킷당 문자열 몇 개(RH:864; 기술 §3).
- 지형 칸 = 1 + 2글자(기술 §3).
- 고스트 = 첫 점은 절대좌표, 나머지는 0.2 m 정수 차이. 모나코 한 랩 1306자(RH:1160).

**짧은 버퍼에서 자르기**: `글자 찾기`·`자르기`를 짧은 버퍼에 쓰면 낱말 길이와 무관하게 블록 수가 같습니다(OBJ설).

**함정** [둘]
- 빈 문자열 `''`은 `0`과 같다고 비교됩니다. 로드 때 `!value → 0`도 됩니다. 글자를 지울 때는 폭 0 문자 `'\u200B'`를 씁니다(RH:1655-1656).
- **함수 지역 변수는 `value || 0`으로 읽힙니다.**(RH:513-517; CP:28; GD:120-127; OB:33)
  - `''`로 시작한 누적이 `0…`이 됩니다. 닉네임이 `0alice`가 되어 랭킹 확인이 영원히 실패했습니다.
  - NaN도 0이 됩니다.
  - 낱말 버퍼에는 `' '`나 `'#'`를 둡니다.
- 비교 블록은 숫자처럼 보이는 문자열을 숫자로 바꿉니다(GD:120-127; OB:49; SM:75-79).
  - `'0' = ' '`가 참입니다. `'1.0'=='1'`도 참입니다.
  - 문자 비교는 `'#'+글자`로 합니다.
- 숫자처럼 보이는 문자열 변수·리스트 값은 불러올 때 숫자로 바뀝니다(SM:75-79; RH:468, 408).
  - [tess]에서 `'0000000000000000'`이 0이 됐습니다.
  - 데이터 문자열은 영문자(`'P'`)로 시작합니다.
- `+`는 한쪽이 `/^-?\d+\.?\d*$/`가 아니면 문자열 이어 붙이기가 됩니다(`" 0123"`, `"1e-30"`)(SM:75).
- `(문자열)의 a~b번째`는 범위 밖이면 오류로 멈추고, a > b면 둘을 바꿉니다. 빈 범위는 쓰지 않습니다(GD:120-127; RH:516).
- `char_at`·`substring`은 범위 밖에서 throw하고 그 스레드만 죽습니다(VL).
- `replace_string`은 `split/join` 구현이라 같은 문자가 전부 바뀝니다(VL).
- `rgb()`에 소수를 넣으면 파랑 채널이 망가집니다(`#d61f23.b33` → 검정). b만 `Math.floor`합니다(RH:1430-1431).

## 9. 복제본·오브젝트 수

- **오브젝트는 2개로 충분합니다**(RH:1349; BD §0)
  - `pen`: 3D·HUD·소리 전부.
  - `txt`: 글상자 하나가 자기 복제본 48~88개를 만듭니다.
- 글상자 칸은 바뀌었을 때만 다시 씁니다(버전 번호 `txV`). 가만히 있는 글자는 비용이 거의 없습니다(RH:1352; 기술 §7).
- 칸 번호 충돌 검사 도구를 둡니다(`slots.mjs`)(RH:1354).
- 단추 75개 = 글상자 하나의 복제본입니다. 눌린 단추는 좌표 나눗셈 두 번으로 계산합니다(CP:92-93).
- **복제본은 만든 엔티티 바로 아래(그 펜 획보다도 아래)에 생깁니다.** 복제본이 복제본을 만들면 새 그림이 뒤에 깔립니다. 원본만 만들게 하고 두 개를 미리 만들어 둡니다(CP:29; 그래퍼설).
- 한 프레임에 만든 복제본이 `when_clone_start`에서 전역을 읽으면 모두 마지막 값을 봅니다. 템플릿을 먼저 맞춘 뒤 복제합니다(VL).
- `when_message` 핸들러는 복제본에도 살아 있어 N+1개가 지수적으로 생깁니다(VL).
- `let obj$name`: 오브젝트 전용 변수로, 복제본마다 따로입니다(ejs)(RH:1351).
- 글상자 함정 (RH:1361-1362; CP:30)
  - [tess]는 `bgColor`가 없는 글상자를 흰 배경으로 그립니다. `'transparent'`를 명시합니다.
  - "크기 정하기"는 (폭×sx + 높이×sy)/2 기준입니다. 줄바꿈 글상자(폭 고정)여야 정확한 배율이 됩니다.
  - `lineBreak:true`는 세로 위치가 엔진마다 다릅니다.
  - 정렬 상수가 반대입니다: 0 = 가운데, 1 = 왼쪽(RH:1654).
- 한두 글자 단추 이름에는 U+00A0을 붙여 폭을 맞춥니다. 보통 공백은 잘립니다(CP:96).

## 10. 그래픽 자동 조절·프레임 페이싱

- **레이싱 AUTO**(RH:689; 소개)
  - 초마다 프레임을 셉니다. 48 미만이 두 번이면 거리 배율 −0.1(최저 0.45, 그 아래면 HIGH로).
  - 57 이상이 다섯 번이면 +0.05.
  - 배율은 setupCam의 LOD·풍경·지형 거리에 곱해집니다.

  - 기준은 57틱입니다. 단계 변경 직후 1초는 판정하지 않습니다.
  - 가장 낮은 단계로도 안 되면 2~4틱에 한 번 그립니다(`skipN`).
- **BR 프레임 페이싱**(BD §2.4)
  - 매 틱에는 마우스 누적과 클릭 래치만 합니다. k틱마다 논리 + 그리기를 합니다.
  - 57 미만이면 k+1. 60이 3초 이어지면 k−1을 시도하고, 실패하면 10초 동안 고정합니다.
  - k > 3이면 그리기 반지름·LOD를 낮춥니다.
- **OBJ 할당량**(OB:70-73)
  - 1초마다 프레임 수와 일한 양으로 다음 할당량을 정합니다.
  - 움직일 때 `cap`과 멈춘 뒤 `capR`는 따로 잽니다.
  - [tess] 목표 72(여유). 채운 초에는 3배씩 늘리고, 못 채운 초의 1.15배를 30초 동안 천장으로 둡니다.
- 그래퍼: "몫의 절반 이상 쓴 프레임"만 일한 프레임으로 셉니다. 안 그러면 tessvm에서 16픽셀 칸에 머뭅니다(CP:50).
- 식이 바뀔 때 비용 추정(`progCost`)으로 예산을 비례 조정합니다(CP:67).
- **엔진 판별**: [tess] 초시계는 틱 × 1/60이라 늘 1/60의 배수입니다. 12프레임 중 9번 이상이면 tessvm으로 봅니다(OB:47). `$TESSVM` 변수도 있습니다(RH:1333).
- 순정에서 못 돌릴 작품은 데이터를 풀지 않고 안내 화면만 띄웁니다. BR은 순정에서 풀기만 몇 분이 걸렸습니다(BH:201-203).
- 로딩 카드: 무거운 준비를 2틱째로 미루면 로딩 화면이 먼저 보입니다(RH:648).
- 온라인에서는 LOADING 보고를 먼저 보내고 0.5 s 뒤에 빌드합니다(RH:380).

### 한도 (실측)
- **한도는 파일 크기가 아니라 프로젝트 문서 크기 약 16 MB입니다**(MongoDB BSON 16 MiB와 일치)(SM:129-134, 183-185; RH:904).

  |---|---|---|

- 레이싱 실측: 16,148,378 B는 성공, 16,194,322 B는 실패. 우리 파일 기준 문턱은 약 16.17 MB로 추정됩니다(RH:903-904).
- **목표는 project.json ≤ 15.5 MB입니다**(SM).
- 기준은 편집기가 저장할 때 보내는 `Entry.exportProject()` JSON입니다.
  - 블록마다 기본 속성(id, x, y, movable…)을 다시 붙입니다. 파일 속 9 MB가 17 MB가 됐습니다.
  - 자작 추정 도구는 약 2 MB 적게 나왔습니다. 실측(`savesize.mjs`)을 믿습니다(BH:190-191).

- 저장은 GraphQL로 보내고 timeout은 20초입니다. 실패하면 크기와 무관하게 "저장 실패"가 뜹니다(SM:113-119).

**순정 실시간 변수**(entryjs 소스 분석)(RH:1171-1177; 기술 §12)
- `set`은 서버 ack를 받아야 로컬 값이 바뀝니다. `set_variable` 블록이 Promise를 기다리므로, 쓰는 동안 잠깐 멈춥니다.
  - 그래서 메뉴·결과 같은 조용한 화면에서만 씁니다.
- 서버 값은 시작 **뒤에** 소켓 `welcome`으로 옵니다. 켠 직후에는 작품 기본값이 읽힙니다.
- 여러 명이 쓰면 last-write-wins이고 CAS가 없습니다.

**검증된 저장 설계**(RH:1176-1178; RH:1120-1125)
1. 동기화 확인을 기다린 뒤 불러옵니다. 그 전 진행분은 더합니다.
2. 읽고 → 합치고 → 내 줄만 씁니다.
3. 2 s 뒤 다시 읽어 **저장한 줄 전체**가 그대로인지 확인합니다.
4. 아니면 무작위 백오프 `rand(0.2,1.6)·min(6,n)` s 뒤 재시도하고, 포기하지 않습니다.
5. 칸이 2400자를 넘으면 앞에서부터 지웁니다(LRU).

**시험 모델(`multi.mjs`)로 재현한 손실**
- 같은 칸 동시 저장에서 한 명 손실, 같은 랭킹 동시 등록에서 3명 중 2명 손실이 났습니다.
- 동시 1위 고스트는 v8에서 JIT=300일 때 10/20 실패, v9에서 0/20(RH:1125, 1174-1175).

**연결·환경 함정**
- **편집 화면에서 작품 주인이 테스트하면 실시간 변수가 꺼집니다**(`isWorkspace && owner` → `disable()`). 작품 페이지에서 시험합니다(RH:1185-1190).
- 서버가 `hasRealTimeVariable: null`이면 순정도 접속하지 않았습니다. 등록은 서버 쪽 조건이라 엔트리에 문의가 필요했습니다(RH:1100-1105).
- 공유 변수(isCloud)는 **정지 때** 전체 값을 API로 저장해 동시 접속에 약합니다(RH:1191).
- 실시간 리스트는 저장 누락이 잦아 변수만 썼습니다(v8). v2.0.0부터는 Entry Sync 확장(`?!이름` 일반 변수)으로 옮겼습니다(RH:1138, 490-498).
- 변수를 번호로 고를 수 없어 `if` 사슬로 고릅니다(RH:506).

**Entry Sync**(RH:495-511; RH:337-338)
- 리스트가 바뀔 때마다 **리스트 전체**를 보냅니다. 서버는 보낸 사람을 빼고 전달하므로 에코가 없습니다.
- 시작 후 4 s 동안은 로컬 변경을 보내지 않습니다.
- 경쟁에서 진 클라이언트가 옛 리스트를 다시 보내 남의 기록이 되돌아갔습니다(약 1/6). 주기적 `selfCheck`로 복구합니다.
- 엔트리 정지 → 시작(새로고침 없이)이면 리스트가 옛 스냅숏으로 돌아갑니다. 1.5 s 뒤부터 믿습니다.
- 스토어판은 tessvm에서 동작하지 않습니다(`window.Entry` 없음).

**[tess] 0.3.9 실시간 변수**
- `{type:'set', data}`를 보내는데 서버는 `value`를 읽습니다. 그래서 쓰기가 전달되지 않습니다(보정 확장 필요)(RH:1198-1199).
- tessvm은 사용자 ID를 `ab****`로 가립니다. 닉네임을 키로 씁니다(RH:1159).

**온라인 동기 경주**
- 위치 보고에 `속도 × (수신 뒤 경과 + RTT/2)`를 더하고, RTT는 ack로 잽니다(RH:449-453).
- RTT 보정 전 위치 오차는 12.2 m, 보정 뒤 3.7 m였습니다(RH:473-474).

## 15. 빌드 파이프라인

**ejs 컴파일러**
- JS 부분집합을 Entry 블록으로 바꿉니다(RH:1641; 기술 §1).
  - `let` → 변수, `let A=[]` → 리스트, `function` → 함수, `let obj$x` → 오브젝트 변수.
  - 같은 소스를 **JS 백엔드**로도 내서 Node 시뮬레이터로 게임 전체를 돌립니다.
- JS 백엔드는 엔트리 버그를 흉내 냅니다. 안 그러면 sim이 버그를 가립니다(RH:517, 548; GH:42).
  - 지역 변수 `||0`, 5000칸 예외, substring 범위, PLUS 규칙, `rand` 반올림.
- 컴파일러 변환 모음
  - `paged.mjs`: 리스트 페이징(GH:12-14).
  - `legacy.mjs`: 옛 사칙 블록(OB:39).
  - `deloop.mjs`: while → 재귀(RT:62).
  - 상수 풀(RT:28).
  - `inline.mjs`(PH).
- 빌드 단계
  - 리스트 크기 가드(5000)(RH:1536).
  - HOT 정렬(뜨거운 리스트를 앞으로)(E3:56).
  - `allocLists`/`unpackLists` 자동 생성(RH:908, 411).
- 빌드 플래그
  - `NOPACK=1`(비교용)(RH:410).
  - `RSRC=<다른 src>`로 옛 소스 A/B(RH:631-634).
  - `TEST=1`/`BENCH=1`(BH:264).
  - `LEGACY=0`(OB:39).
- ejs 제약
  - `const X=[...]` 불가.
  - 매크로는 식으로 쓸 수 없음.
  - 매개변수 이름 `R`은 런타임 객체를 가림(BH:316-320; RH:1364).
- 큰 데이터는 빌드가 .ent에 직접 넣습니다.
  - OBJ: `모델 넣기.html`이 같은 소스를 JS로 돌려 채운 리스트를 담습니다(314 KB에 0.4 s). 순정 파싱은 낱말당 블록 135개, 꼭짓점 하나에 약 1 ms라 외부 전처리가 필수입니다(OB:54; OBJ설).
  - SmolLM: `node --max-old-space-size=8000`, 9.4 s에 68.5 MB .ent. 값만 복사하는 패치 도구 `state_copy.mjs`(SM:14-19, 87).
- 실제 데이터 파이프라인(레이싱 `real/`): OSM·SRTM·f1-circuits를 받아 빌드 입력 JSON을 만듭니다. Overpass는 자주 바쁘고 User-Agent가 필요합니다(RH:838-860).

**운영 함정**
- 빌드를 동시에 둘 돌리지 않습니다(`.pack` 임시 폴더 공유). 시험 중에 src를 고치지 않습니다(OB:24, 27).
- src는 LF로 통일합니다. CRLF면 여러 줄 문자열 치환이 조용히 실패합니다(RH:1519).
- Bash heredoc의 따옴표와 `\n`은 깨질 수 있습니다. 편집 스크립트는 파일로 써서 node로 돌립니다(RH:1433; CP:36).
- PowerShell `R`은 Invoke-History 별칭입니다(BH:110).
- node 코드 안의 `/tmp` 문자열은 `C:\tmp`가 됩니다(RH:1434).
- 로컬 `server.js` `/api/export` 본문 한도가 25 MB라 413이 났습니다. `ENT_MAX_MB`로 올렸습니다(SM:98-102).
- 로컬 편집기 `entry.min.js`를 playentry 최신판으로 바꿔 둡니다. 엔진 판 차이가 결과를 바꿉니다(GH:11).

**시험 문화**
- 기능마다 `t9/*.mjs` PASS/FAIL 시험을 둡니다.
- 옛 소스(`RSRC`)로는 FAIL이 나는지 확인해 시험이 버그를 잡는지 봅니다(RH:35, 156, 347).
- 결정적 계산은 순정·tess·Node가 소수점 아래까지 같습니다. Node로 검증할 수 있습니다(물리설).
- 경계 시험: 리스트를 97칸으로 줄이기, 임계값 낮추기, 새 칸을 쓰레기로 채우기(`mp_poison`)(GD §5).
