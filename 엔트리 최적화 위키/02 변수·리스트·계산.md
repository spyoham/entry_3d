# 02. 데이터·계산 블록의 비용과 숫자 규칙 (변수 · 리스트 · 계산 · 판단 · 문자열)

> 기준 소스: `entryjs` commit `e01b81b` (2026-09-16). 경로는 모두 `entryjs/src/` 기준.
> 속도 수치는 Node v24(V8)에서 **엔트리와 같은 `extern/util/bignumber.min.js`(v4.0.4)** 와 블록 함수 본문을 그대로 옮겨 잰 마이크로벤치다. 브라우저(Chrome)도 V8이라 **비율은 비슷할 것(추정)**. 절대값보다 "몇 배 차이인가"로 읽을 것.
> 블록 하나를 실행하는 공통 비용(Scope 생성, 이벤트 발송, 틱 스케줄링)은 이 문서 범위 밖이다. 여기서는 **블록 본문이 하는 일**만 다룬다.

---

## 0. 먼저 알아야 할 공통 규칙

### 0.1 값 블록은 "인자를 전부 먼저" 계산한다
`Scope.run()` 은 `getParams()` 로 **모든 인자 블록을 먼저 평가**한 뒤 블록 함수를 부른다 (`playground/scope.js:187-209`, `36-46`). 인자 블록마다 `new Entry.Scope(...)` 객체를 하나씩 만든다 (`scope.js:40`).
- 그래서 `getValue/getNumberValue/getStringValue` 는 이미 구한 값 배열을 읽기만 한다 (`scope.js:93-95`). **같은 인자를 두 번 읽어도 다시 계산하지 않는다.**
- 반대로 **단락 평가(short-circuit)가 없다.** `그리고/또는` 의 오른쪽, 쓰지 않는 인자도 항상 계산된다 (5.2절).

### 0.2 형 변환 3종 (모든 블록이 이걸 씀)
| 함수 | 정의 | 결과 예 |
|---|---|---|
| `getNumberValue` | `parseFloat(v) \|\| 0` (`scope.js:139-141`) | `"12abc"`→12, `"abc"`→0, `NaN`→0, `""`→0, `"0x10"`→0, `".5"`→0.5, `true`→0, `Infinity`→Infinity |
| `getStringValue` | `String(v)` (`scope.js:135-137`) | 숫자 1e21 → `"1e+21"`, 1e-7 → `"1e-7"` |
| `getBooleanValue` | `undefined`→false, 아니면 `Number(v)`가 NaN이면 true, 아니면 그 숫자 (`scope.js:143-150`) | `"0"`→거짓, `""`→거짓, `"false"`→**참**, `"abc"`→참 |

`만약`·`~인 동안 반복` 등 흐름 블록의 조건은 `getBooleanValue` 를 쓴다 (`playground/blocks/block_flow.js:286, 406, 479, 549`).

### 0.3 "숫자인가?" 판정 = 정규식
`Entry.Utils.isNumber` (`util/utils.js:470-479`):
```js
if (typeof num === 'number') return true;              // NaN, Infinity 도 true
const reg = /^-?\d+\.?\d*(?:[eE][+-]?\d+)?$/;
```
- **문자열 `".5"`, `"+5"`, `" 5"`, `"5 "`, `"Infinity"`, `"0x10"` 은 숫자가 아니다.** `"1."`, `"-0.5"`, `"1e+21"` 은 숫자.
- 이 판정이 `+` 의 "더하기냐 이어붙이기냐", 변수 `~만큼 바꾸기`, 리스트 인덱스 검사에 쓰인다.

### 0.4 어떤 정의가 실제로 쓰이나
`Entry.block = Object.assign(Entry.block, getBlocks(), blocks.getBlocks())` (`playground/block_entry.js:8083`). 레거시 파일 `block_entry.js` 를 먼저 넣고 `playground/blocks/*.js` 로 **덮어쓴다.** 그래서
- `calc_basic`, `boolean_basic_operator`, 리스트/변수 블록 등은 `playground/blocks/*` 정의가 살아 있다.
- `number`·`text`·`angle`·`True`·`False` (`block_entry.js:956, 993, 3192, 3214, 3288`) 와 **팔레트에 없는 레거시 블록** `calc_plus/calc_minus/calc_times/calc_divide/calc_mod/calc_share` (`block_entry.js:1209-1450`), `options_for_list` (`3326`) 는 덮어쓰이지 않아 **그대로 실행 가능한 상태**로 남아 있다 (팔레트 목록 `extern/util/static.js:199-227` 에는 없음). 3.7절 참고.
- `number`/`text` 블록은 입력칸 값을 그대로 돌려준다 (`block_entry.js:973-975`). 프로젝트 JSON에서 `params:["10"]` 이면 **문자열 `"10"`** 이다.

### 0.5 블록 안에서 예외가 나면 프로젝트 전체가 멈춘다
실행기는 예외를 잡아 `Entry.Utils.stopProjectWithToast` 를 부르고 (`playground/executors.js:50-66`), 이 함수는 실행 중이면 `engine.toggleStop()` 을 호출한다 (`util/utils.js:2160-2172`). 리스트 범위 밖 접근, `char_at` 범위 밖, `asin(2)` 등은 **해당 스레드가 아니라 작품 전체 정지**다.
(※ `entry-vibe-coding/knowledge/07-runtime-quirks.md` 의 char_at 절은 "그 스레드만 죽는다"고 적었는데, 현재 소스 기준으로는 엔진 정지다. 문서 쪽 갱신 필요.)

### 0.6 Promise를 돌려주는 블록은 그 스레드를 최소 1틱 쉬게 한다
블록이 `Promise` 를 돌려주면 실행기가 `paused = true` 후 루프를 빠져나가고 (`executors.js:75-79`), 틱 루프는 멈춘 실행기를 건너뛴다 (`playground/code.js:170`). 실시간/공유 변수·리스트 블록이 여기에 걸린다 (1.7절).

## 1. 변수

### 1.1 변수 찾기 = 매번 선형 탐색
모든 변수 블록은 실행할 때마다 ID로 변수를 다시 찾는다.
```js
// class/variable_container.js:1353-1361
getVariable(id_, entity = {}) {
    const criteria = { id_ };
    let variable = _.find(this.variables_, criteria);          // 전체 변수 배열 선형 탐색
    if (entity.isClone && variable.object_) {
        variable = _.find(entity.variables, criteria);          // 클론이면 한 번 더
    }
    return variable;
}
```
- `variables_` 는 **프로젝트의 모든 변수**(전역 + 모든 오브젝트의 지역 변수)가 든 배열. 캐시나 Map이 없다. 리스트도 똑같다 (`getList`, `variable_container.js:1367-1375`, `lists_` 배열).
- lodash `_.find(arr, {id_})` 실측 (평균 위치 기준):

| 프로젝트 변수 수 V | 1회 조회 |
|---|---|
| 10 | ~100 ns |
| 50 | ~150 ns |
| 200 | ~355 ns |
| 1000 | ~1.75 µs |

→ 원소당 ~1.7 ns + 고정 ~90 ns. **배열 앞쪽에 있는 변수일수록 빨리 찾는다.** 배열 순서는 저장된 프로젝트의 `variables` 순서(대체로 만든 순서)다 (추정: `setVariables` 가 저장 순서대로 넣음).

### 1.2 블록별 비용

| 블록 | 하는 일 (근거) | 비용 |
|---|---|---|
| `get_variable` (변수 값) | `getVariable` → `getValue()` → `value_` 반환 (`block_variable.js:337-341`, `variable.js:313-324`) | 조회 1회. 변환 없음, **저장된 형(숫자/문자열)을 그대로** 돌려줌 |
| `set_variable` (~를 ~로 정하기) | 값을 **변환 없이** `setValue(value)` (`block_variable.js:583-600`) | 조회 + `setValue`(1.3절) |
| `change_variable` (~에 ~만큼 더하기) | 아래 1.4절 | 조회 + **BigNumber 덧셈 + 정규식 4회 + `toFixed`** → 결과는 **문자열** |
| `show_variable` / `hide_variable` | `setVisible` (+show는 `updateView` 한 번 더) (`block_variable.js:679-685, 756-760`) | 값이 같으면 즉시 반환 (`variable.js:380-382`) |

### 1.3 `setValue()` 와 화면 갱신 — 숨기면 얼마나 아끼나
```js
// class/variable/variable.js:338-343
setValue(value) {
    if (!this.isRealTime_) {
        this.value_ = value;
        this._valueWidth = null;
        this.updateView();
        Entry.requestUpdateTwice = true;
```
`updateView()` (`variable.js:184-237`):
- `this.view_` 가 없으면 즉시 반환 (`185-187`). **클론의 지역 변수는 뷰를 만들지 않으므로 이 비용이 0**이다 (클론 복사본은 `isClone:true` 로 생성, `variable.js:72, 552-554`).
- **보이는 변수**: 이름 문자열 조립(지역 변수면 `Entry.container.getObject` 선형 탐색까지, `193-199`), 값 텍스트 설정, 텍스트 폭 측정(`getMeasuredWidth`), 상자 2개 다시 그리기(`_adjustSingleViewBox`, `246-261`). WebGL 모드에서 텍스트가 바뀌면 `PIXIText.updateText` 가 **캔버스에 글자를 다시 그리고 텍스처를 갱신**한다 (`class/pixi/text/PIXIText.js:54-57, 93-260`). → 값을 바꿀 때마다 글자 래스터화.
- **숨긴 변수**: 위 블록 전체를 건너뛴다(`189`). 그래도 남는 일:
  - `bpReplace(this.id_, x, y, this.getRealWidth(), this.getRealHeight())` (`235`) — 인자인 `getRealWidth()` 가 텍스트 측정을 2번, `getRealHeight()` 가 1번 호출 (`456-462, 482-484`). WebGL에서는 글자가 안 바뀌었으면 캐시라 싸고, createjs(캔버스) 모드에서는 매번 `measureText` (추정: createjs Text 는 측정 캐시가 없음).
  - `bpReplace` 는 `_throttle(VariableBP.replace)` 인데 **대기 시간을 안 줘서**(`variable.js:10`) lodash 기준 wait=0 → 매 호출 실행 + 매번 `clearTimeout/setTimeout` (lodash `debounce.js:176-177`). Node 실측 ~200 ns/회.
  - `Entry.requestUpdate = true` (`236`) + `Entry.requestUpdateTwice = true` (`343`) → **무대가 이번 틱과 다음 틱 두 번 다시 그려진다** (`class/stage.js:165-189`). 숨긴 변수여도 마찬가지. 3D처럼 매 프레임 어차피 다시 그리는 작품에선 손해 없음, **계산만 하는 프레임(LLM 추론 등)에선 불필요한 렌더 2회**.
- 결론: **숨기면 텍스트 래스터화·도형 재그리기가 사라진다(가장 큰 몫).** 하지만 `setValue` 자체가 0원이 되지는 않는다 (조회 + throttle + 렌더 요청).
- 값 표시는 소수 둘째 자리 반올림 표시일 뿐이다 (`toFixed(2).replace('.00','')`, `variable.js:209-216`). **저장 값은 안 바뀐다.**

### 1.4 `change_variable` (~만큼 더하기) — 느리고, 문자열이 되고, 작은 수를 버린다
```js
// playground/blocks/block_variable.js:439-457
if (value == false && typeof value === 'boolean') throw new Error('Type is not correct');
...
if (Entry.Utils.isNumber(value) && variable.isNumber()) {
    value = Entry.parseNumber(value);
    variableValue = Entry.parseNumber(variableValue);
    fixed = Entry.getMaxFloatPoint([value, variable.getValue()]);
    sumValue = new BigNumber(value).plus(variableValue).toNumber().toFixed(fixed);
} else {
    sumValue = `${variableValue}${value}`;           // 둘 중 하나라도 숫자가 아니면 이어붙이기
}
```
`getMaxFloatPoint` 는 `String(n)` 에서 `'.'` 뒤 글자 수를 센다 (최대 20) (`util/utils.js:1763-1776`).

실측(같은 코드 재현):

| 변수 값 | 더할 값 | 결과(저장값) | 문제 |
|---|---|---|---|
| 0 | 1 | `"1"` | **숫자가 아니라 문자열** |
| 1.5 | 1.5 | `"3.0"` | 소수 자릿수가 "달라붙음" |
| `"3.0"` | 1 | `"4.0"` | 한 번 붙은 자릿수는 `정하기` 전까지 안 사라짐 |
| 0 | 1e-7 (계산 결과) | `"0"` | **`String(1e-7)="1e-7"` 에 '.'이 없어 fixed=0 → 0으로 반올림** |
| 0.5 | 1.2e-7 | `"0.5000"` | 증분이 통째로 사라짐 |
| 0 | `"0.0000001"`(입력칸 문자열) | `"0.0000001"` | 문자열 리터럴이면 괜찮음 |
| 1e21 | 1 | `"1e+21"` | `toFixed` 가 지수 표기 반환 |
| (누적) | 0.30000000000000004 ×10 | `"3.00000000000000044"` | 17자리 `toFixed` 가 이진 오차를 그대로 노출 |
| 5 | 참(true) | `"5true"` | 거짓(false)이면 **예외 → 작품 정지** |
| `"abc"` | 1 | `"abc1"` | |

비용: BigNumber 생성·덧셈·`toNumber` + `String()` 2회 + `toFixed` + `isNumber/parseNumber` 정규식 4회. Node에서 실수 0.5씩 누적 기준 **~0.9 µs/회** (단순 JS 덧셈은 ~1 ns).
→ **물리·신경망처럼 작은 실수를 누적하는 곳에 `~만큼 더하기` 를 쓰면 값이 조용히 틀린다.** `변수를 (변수 + x)로 정하기` 를 쓸 것 (결과가 숫자로 유지되고 지수 표기 문제 없음, 3.1절).

### 1.5 지역 변수 · 클론 · 함수 지역 변수

| 종류 | 조회 | 쓰기 | 화면 갱신 | 근거 |
|---|---|---|---|---|
| 전역 변수 | `_.find(variables_)` 1회 | `setValue`+`updateView` | 있음(보이면 큼) | 1.1, 1.3 |
| 오브젝트 지역 변수 (원본 실행) | 1회 | 같음 + 보이면 `getObject` 선형 탐색 | 있음 | `variable.js:193-199` |
| 오브젝트 지역 변수 (**클론**에서) | `_.find` **2회** (전체 배열 → 클론의 `entity.variables`) | `setValue`, 그러나 `view_` 없음 → `updateView` 즉시 반환 | **없음** | `variable_container.js:1355-1358`, `variable.js:185-187` |
| **함수 지역 변수** (`set_func_variable`/`get_func_variable`) | `getFunction(funcId)` (객체 키, O(1)) + 그 함수의 지역 변수 몇 개 선형 탐색 + `variableId.split('_')` | 객체 필드 대입만 | **없음**, 렌더 요청도 없음 | `block_func.js:160-168, 261-266`, `class/function.js:180-194` |

- 함수 지역 변수 읽기는 `localVariable?.value || 0` (`function.js:185`) → **`""`, `false`, `NaN` 이 0으로 바뀐다.**
- 함수 호출마다 지역 변수 배열을 `_cloneDeep` 한다 (`block_func.js:390`) → 함수 지역 변수가 많을수록 호출이 비싸다 (지역 변수 수에 비례).
- 클론 생성 시 그 오브젝트의 지역 변수·리스트를 전부 `clone()` → `toJSON()` 하는데, 리스트는 `JSON.parse(JSON.stringify(array))` 로 **통째 깊은 복사** (`class/object.js:661-669`, `listVariable.js:523-530`). **큰 지역 리스트를 가진 오브젝트를 복제하면 클론 1개마다 리스트 전체 복사.**
- 변수 객체를 만들 때마다 `workspaceChangeMode` 리스너를 등록하고 지우지 않는다 (`variable.js:86`, `util/eventHandler.js:6-19`). 지역 변수가 있는 오브젝트의 클론을 계속 만들면 리스너가 쌓인다 (메모리, 추정: 실행 중 영향은 작음).

### 1.6 공유 변수(isCloud) / 실시간 변수(isRealTime)
- 실시간 변수: `getValue()` 가 매번 `cloudVariable.get()` 조회 (`variable.js:313-324`), 값이 0/빈 문자열이면 로컬 `value_` 로 대체(`322`). `setValue()` 는 소켓으로 `action` 을 보내고 **서버 응답을 기다리는 Promise** (`variable.js:344-363`, `extensions/CloudVariable.js:186-201, 239-253`) → 블록마다 **최소 1틱 + 왕복 지연**(0.6절).
- `add_value_to_list` 는 `isRealTime_` 가 아니라 **`isCloud_`** 로 분기한다 (`block_variable.js:981-993`). 공유(클라우드) 리스트면 실시간이 아니어도 Promise 로 감싸서 돌려주므로 **항목 추가 1회마다 스레드가 1틱 쉰다**(추정: `await undefined` 가 즉시 풀려도 실행기는 다음 틱에 재개).
- 내부 루프에서 쓰는 변수·리스트는 절대 공유/실시간으로 만들지 말 것.

### 1.7 타이머 · 대답 · 슬라이더 변수
- `초시계 값` = `projectTimer.getValue()` (`block_calc.js:1094-1096`). 초시계는 `setInterval(…, 1000/60)` 으로 갱신된다 (`class/engine.js:1176-1189, 1227-1245`). **한 틱 안에서 동기적으로 도는 계산 도중에는 값이 변하지 않는다** → 같은 틱 안 구간 측정 불가. 초시계가 돌면 1/60초마다 `setValue` → 무대 렌더 요청.
- 슬라이더 변수: `getValue()` 마다 `isNumber`(정규식) + `Number()` (`slideVariable.js:221-228`), `setValue` 는 `Number()` 후 최솟값/최댓값으로 자름 (`230-240`). 일반 변수보다 조금 비싸고 값이 잘린다.

## 2. 리스트

### 2.1 저장 구조와 한계
- 내부는 `array_ = [{data: 값}, ...]` (`listVariable.js:227-229`). 값은 **형 변환 없이** 저장 (숫자는 숫자, 문자열은 문자열).
- **최대 5000개.** `LIST_MAX_LENGTH = 5000` (`listVariable.js:6-8`).
  - 넘치면 `array_.slice(-5000)` → **앞쪽(오래된) 항목이 버려지고** 경고 토스트 (`10-23`). 추가·삽입 때마다 검사(`230, 287`). 5000개 상태에서 계속 추가하면 **추가 1회마다 5000개 배열 복사 + 토스트**.
  - 프로젝트를 불러올 때도 5000개 초과분은 앞에서 잘라내고 알림창 (`29-40`).
  - 삽입으로 넘치면 맨 앞 항목이 잘리므로, **1번 자리에 삽입하면 방금 넣은 값이 바로 버려진다.**

## 3. 계산 블록 — 정확한 숫자 규칙

### 3.1 `calc_basic` (+ − × ÷) — 전부 BigNumber
```js
// playground/blocks/block_calc.js:156-186
let leftValue = script.getNumberValue('LEFTHAND', script);
let rightValue = script.getNumberValue('RIGHTHAND', script);
if (operator === 'PLUS') {
    const leftStringValue = script.getValue('LEFTHAND', script);
    const rightStringValue = script.getValue('RIGHTHAND', script);
    if (!Entry.Utils.isNumber(leftStringValue)) leftValue = leftStringValue;
    if (!Entry.Utils.isNumber(rightStringValue)) rightValue = rightStringValue;
    if (typeof leftValue === 'number' && typeof rightValue === 'number')
        return new BigNumber(leftValue).plus(rightValue).toNumber();
    else return leftValue + rightValue;                // 문자열 이어붙이기
}
leftValue = new BigNumber(leftValue); rightValue = new BigNumber(rightValue);
// MINUS → minus, MULTI → times, 그 외 → dividedBy  (모두 .toNumber())
```
- BigNumber 라이브러리: `extern/util/bignumber.min.js` **v4.0.4**, 설정은 `BigNumber.config({ ERRORS: false })` 뿐 (`util/init.js:113`) → 기본값 **DECIMAL_PLACES=20, ROUNDING_MODE=4(HALF_UP)** (`bignumber.min.js` 안의 `B=20,P=4`).
- **더하기(+) 규칙**: 양쪽 원래 값이 `isNumber` 를 통과해야 숫자 덧셈. 아니면 **원래 값끼리 JS `+`** (= 이어붙이기).
  - `"1"+"2"`→3, `"안녕"+"하세요"`→`"안녕하세요"`, `"1"+"개"`→`"1개"`
  - **`".5"+1` → `".51"`**, **`" 1"+2` → `" 12"`**, `"Infinity"+1` → `"Infinity1"`, `""+1` → `"1"` (전부 이어붙이기)
  - `true+1` → 2 (불리언은 typeof number는 아니지만 isNumber 실패 → 원래 값 `true` + 1 = 2), `NaN+1` → 1 (NaN은 typeof number라 숫자 경로, `parseFloat(NaN)||0` = 0)
- **− × ÷** 는 `getNumberValue` 만 쓰므로 `"abc"*2`→0, `"12abc"*2`→24, `"0x10"*1`→0.
- **정밀도 결과**:
  - 덧셈·뺄셈·곱셈은 두 수의 **짧은 10진 표현**으로 정확히 계산 후 double로 반올림 → `0.1+0.2 = 0.3`, `1.1×1.1 = 1.21`, `0.1×3 = 0.3` (JS는 각각 0.30000000000000004, 1.2100000000000002, 0.30000000000000004). 결과 정밀도 자체는 여전히 double (`2^53+1 = 9007199254740992`).
  - **나눗셈은 소수점 아래 20자리에서 반올림** → 작은 몫은 유효숫자를 잃는다:
    | 식 | 엔트리 | JS |
    |---|---|---|
    | 1e-7 ÷ 3 | 3.333333333333e-8 (13자리) | 3.3333333333333334e-8 |
    | 1e-15 ÷ 7 | **1.4286e-16** (5자리) | 1.4285714285714286e-16 |
    | 1 ÷ 1e21, 1 ÷ 3e20 | **0** | 1e-21, 3.33e-21 |
    | 1 ÷ 0 / 0 ÷ 0 | Infinity / NaN | 같음 |
  - 곱셈은 이 제한이 없다 (`1e-10×1e-10 = 1e-20`, `1e-25×1 = 1e-25`). **작은 수로 나눌 일이 있으면 역수를 곱하는 편이 정밀하다.**
  - NaN이 변수에 들어가면 다음 계산에서 `getNumberValue` 가 0으로 바꾼다 (0.2절) → NaN이 퍼지지 않고 **조용히 0**이 된다.
- **비용 (Node 실측, 1회)**:

  | 연산 | 정수 피연산자 | 일반 실수 피연산자 |
  |---|---|---|
  | + | ~170–230 ns | **~1.2 µs** |
  | − | — | **~1.3 µs** |
  | × | ~280–440 ns | **~1.4–1.6 µs** |
  | ÷ | ~1.7 µs | **~2.0–2.7 µs** |
  | 참고: JS 네이티브 `a*b` | ~8 ns | ~8 ns |
  | 참고: `몫` 블록 본문 `Math.floor(a/b)` | ~6–9 ns | |

  BigNumber 는 숫자를 문자열로 바꿔 파싱해 자릿수 배열로 계산하므로, **소수(비정수)가 섞이면 4~7배 느려진다** (소수 4자리로 반올림한 값도 ~1.1 µs, 정수 경로만 빠름).

### 3.2 `calc_rand` (~부터 ~사이의 무작위 수)
```js
// block_calc.js:294-306
const leftValue = script.getStringValue('LEFTHAND', script);
const rightValue = script.getStringValue('RIGHTHAND', script);
const left = Math.min(leftValue, rightValue);  const right = Math.max(leftValue, rightValue);
if (Entry.isFloat(rightValue) || Entry.isFloat(leftValue))
    return (Math.random() * (right - left) + left).toFixed(2);       // 문자열!
else
    return Math.floor(Math.random() * (right - left + 1) + left);
```
- 실수/정수 결정은 **입력의 문자열 모양**: `Entry.isFloat = /\d+\.{1}\d+$/` (`util/utils.js:1684-1686`). `"1.0"`, `"0.5"` → 실수 / `"1"`, `"1."`, `"1e-3"`, 계산 결과 숫자 1 → 정수.
  - `무작위(0, 1)` → 0 또는 1. `무작위(0, 1.0)` → 실수.
- 실수 결과는 **`toFixed(2)` 문자열 → 0.01 단위밖에 안 나온다.** 범위가 0~1이면 101가지 값뿐이고 양 끝은 반올림 때문에 절반 확률.
- `무작위(0, 1e-7)` → 정수 경로 → 0.
- 숫자가 아닌 입력 → NaN.
- 몬테카를로·광선 지터처럼 고운 난수가 필요하면 **정수 무작위(예: 0~999999) 후 스케일**.

### 3.3 `quotient_and_mod` (몫 / 나머지) — 네이티브라 빠르다
```js
// block_calc.js:650-659
const left = script.getNumberValue('LEFTHAND', script);
const right = script.getNumberValue('RIGHTHAND', script);
if (operator === 'QUOTIENT') return Math.floor(left / right);
else return left - right * Math.floor(left / right);
```
- 바닥(floor) 나눗셈, 나머지는 **나누는 수의 부호**를 따름: `-1 나머지 2 = 1`, `-1 몫 2 = -1`. (07-runtime-quirks.md 1404절과 일치)
- BigNumber 를 안 쓰므로 실수 오차가 그대로: `5.3 나머지 1 = 0.2999999999999998`.
- 0으로 나누면 몫 ±Infinity/NaN, 나머지 NaN.
- 비용은 `getNumberValue` 2회 + 네이티브 연산 → **÷ 블록보다 수백 배 싼 정수 나눗셈**.

### 3.4 `calc_operation` (제곱, 루트, 삼각함수, …)
`block_calc.js:756-812`. 입력은 `getNumberValue`(숫자 아니면 0).

| 연산 | 구현 | 비고 |
|---|---|---|
| 제곱 `square` | `value * value` | **네이티브 곱셈.** `x×x` 를 calc_basic으로 하는 것보다 훨씬 쌈 |
| 루트 `root` | `Math.sqrt` | 음수 → NaN |
| sin/cos/tan | `Entry.preciseTrig(value, op)` (`util/utils.js:1520-1531`) | **입력은 도(degree).** `angle = degrees % 360` 후 0,30,45,60,90,…,360 이면 표에서 정확값(`1460-1518`; tan 90 = Infinity, tan 270 = -Infinity), 아니면 `Math.sin(angle*π/180)`. **음수 각은 표를 못 탐** (`-30 % 360 = -30`) → `sin(-180) = -1.22e-16` |
| asin/acos/atan | `Entry.toDegrees(Math.asin(v))` 등 | **결과는 도.** 옵션 이름이 `asin_radian` 이지만 도로 돌려줌. asin/acos 는 \|x\|>1 이면 **예외 → 작품 정지** (`759-762`). **atan2 없음** |

| 소수점 부분 `unnatural` | BigNumber `value − floor(value)`, 음수면 `1 − 결과` | 느림(BigNumber). -2.3 → 0.3 (절댓값의 소수부) |
| 내림/올림/반올림/절댓값 | `Math.floor/ceil/round/abs` | 반올림은 JS 규칙: `round(-2.5) = -2`, `round(2.5) = 3` |

## 4. 문자열 블록

모두 `getStringValue`(= `String()`) 로 받는다. 숫자를 넣으면 매번 숫자→문자열 변환 (1e21 이상, 1e-7 이하는 지수 표기).

| 블록 | 본문 (근거) | 비용 / 주의 |
|---|---|---|
| `length_of_string` | `.length` (`block_calc.js:1629-1631`) | O(1). UTF-16 단위: 한글 1글자=1, 이모지=2 |
| `combine_something` (합치기) | `` `${a}${b}` `` (`1760-1765`) | V8은 긴 문자열 이어붙이기를 지연 결합(rope)으로 처리 → 반복 합치기는 대체로 싸고, 처음 인덱싱할 때 한 번 평탄화 비용 (추정, V8 내부 동작) |
| `char_at` (n번째 글자) | `index = getNumberValue - 1`; `index<0 \|\| index>len-1` 이면 **예외** (`1848-1856`) | O(1). 소수 인덱스(1.5)는 범위 검사를 통과하고 `str[0.5]` = **undefined 반환** |
| `substring` (a~b번째 글자) | 범위 밖이면 예외, `substring(min, max+1)` (`1986-1996`) | O(길이). 시작>끝이면 **뒤집어서** 잘라줌 |
| `index_of_string` (위치) | `indexOf + 1`, 없으면 0 (`2152-2157`) | O(n) |
| `count_match_string` | `split(target).length - 1` (`2073-2077`) | O(n) + 배열 할당 |
| `replace_string` | `split(old).join(new)` (`2257-2262`) | **전부** 바꿈, O(n) + 배열 할당 |
| `reverse_of_string` | `split('').reverse().join('')` (`1681-1685`) | O(n) + 배열 할당, 이모지(서로게이트 쌍) 깨짐 |
| `change_string_case` | `toUpperCase/toLowerCase` (`2343-2352`) | O(n) |
| `is_type` (숫자/영어/한글인가) | `isNumber` 정규식 등 (`block_judgement.js:302-316`) | `".5"`, `" 5"` 는 숫자 아님 |

큰 수 연산을 문자열 + `char_at` 으로 자릿수마다 하면 **자릿수마다 블록 2~3개(조회·변환·범위검사)** 가 돈다. 리스트에 큰 기수(예: 10^7) 덩어리로 저장하는 편이 블록 수가 수 배 적다 (6장 규칙 9).

## 5. 비교·논리 블록

### 5.1 `boolean_basic_operator` (=, ≠, >, <, ≥, ≤)
```js
// block_judgement.js:474-507
if (typeof leftValue === 'string' && leftValue.length) {
    const leftNumber = Number(leftValue);
    if (!isNaN(leftNumber)) leftValue = leftNumber;
}   // 오른쪽도 동일
switch (operator) {
    case 'EQUAL':     return leftValue === rightValue;   // 엄격 비교
    case 'NOT_EQUAL': return leftValue != rightValue;    // 느슨한 비교 (!)
    case 'GREATER':   return leftValue > rightValue; ...
```
- 숫자로 바꾸는 기준은 `isNumber` 가 아니라 **JS `Number()`**: `" 12 "`→12, `"0x10"`→16, `"1e3"`→1000, `"Infinity"`→Infinity, `"1.0"`→1 로 바뀐다. 빈 문자열은 그대로 `""`.

| 비교 | 결과 | 이유 |
|---|---|---|
| `"1.0" = 1` | 참 | 둘 다 숫자 1 |
| `"abc" = "ABC"` | 거짓 | 대소문자 구분 |
| `"" = 0` | 거짓 | `""` 는 변환 안 됨, `===` |
| `"" ≠ 0` | **거짓** | `!=` 느슨 비교에서 `"" == 0` 이 참 → `=`도 `≠`도 거짓 |
| `" " = 0` | 참 | `Number(" ")` = 0 |
| `"0x10" = 16` | 참 | |
| `"10" > "9"` | 참 | 숫자 비교 |
| `"b" > "a"` | 참 | 문자열 사전순(UTF-16 코드) |
| `"a" > 1`, `"a" < 1` | 둘 다 거짓 | `"a"` → NaN 비교 |
| `참 = 1`, `참 ≠ 1` | 둘 다 거짓 | `===` 는 거짓, `!=` 는 `true == 1` 이라 거짓 |
| `"true" = 참` | 거짓 | |
| NaN = NaN | 거짓 | |

- 비용: 문자열 피연산자일 때만 `Number()` 파싱 1회. 숫자끼리는 거의 0. **변수가 `~만큼 더하기` 때문에 문자열이 돼 있으면 비교할 때마다 파싱**한다.

### 5.2 `boolean_and_or`, `boolean_not`
- `그리고/또는`: `Boolean(left)`, `Boolean(right)` 후 `&&`/`||` (`block_judgement.js:605-619`). **양쪽 인자는 블록 실행 전에 이미 계산됨**(0.1절) → 단락 평가 없음. 오른쪽에 리스트 접근이 있으면 범위 밖 예외가 그대로 난다 (07-runtime-quirks.md 130절과 일치).
- `Boolean()` 은 `getBooleanValue` 와 규칙이 다르다: **`"0"` 은 `그리고/또는` 에서 참, `만약` 조건에서는 거짓** (0.2절).
- `~가 아니다`: `!getBooleanValue` (`686-688`) → `"0"`, `""` 의 부정은 참.
- 레거시 `boolean_and` (`block_entry.js:3034`)는 `getBooleanValue` 를 써서 규칙이 또 다르다 (참고만).

### 5.3 기타 판단 블록
- `is_clicked`: 필드 읽기 O(1) (`block_judgement.js:26-28`).
- `is_press_some_key`: `Entry.pressedKeys.indexOf(keycode)` — 눌린 키 수에 비례, 사실상 O(1) (`101-104`).
- `reach_something`: 픽셀 충돌 `ndgmr.checkPixelCollision` 을 대상 원본 + **모든 클론**에 대해 돌림 (`162-236`) → 클론 수에 비례하고 1회 비용도 큼. 대상 오브젝트도 `getEntity` 선형 탐색.

## 6. 최적화 규칙 (효과 큰 순)

1. **계산에 쓰는 리스트는 무조건 숨긴다.** 보이는 리스트는 추가/삽입/삭제/바꾸기 1회마다 보이는 행 전부를 새로 만들고(WebGL이면 행마다 `<canvas>` 2개 생성), 글자 폭을 반복 측정한다. (`listVariable.js:344-475`, `PIXIText.js:12-22`)
2. **루프 안에서 실수 `+ − × ÷` 개수를 줄인다.** calc_basic 은 BigNumber 라 실수 연산 1회 ~1.2–2.7 µs (네이티브의 150~300배). 공통 부분식을 변수에 한 번 계산해 재사용하고, 같은 값으로 여러 번 나누면 역수를 한 번 구해 곱한다. (`block_calc.js:156-186`)
3. **네이티브 경로를 쓸 수 있으면 쓴다**: `x×x` 대신 `calc_operation 제곱`(`value*value`), 정수 나눗셈·내림 나눗셈은 `÷`+`내림` 대신 **`몫`** (`Math.floor(a/b)`, ~수 ns), 나머지는 `나머지`. 거리는 `distance_something`. (`block_calc.js:650-659, 774-776, 1488-1503`)
4. **실수를 누적할 땐 `~만큼 더하기` 대신 `~를 (~ + x)로 정하기`.** `change_variable` 은 결과를 `toFixed` 문자열로 만들고, 1e-7 같은 지수 표기 증분을 **0자리로 반올림해 버린다** (`0.5 += 1.2e-7 → "0.5000"`). 정수 카운터(`i += 1`)에만 쓸 것. (`block_variable.js:447-454`, `util/utils.js:1763-1776`)
5. **고정소수점 정수 계산** — Node에서 BigNumber 본문만 재면 정수가 4~7배 빠르지만, **실제 엔진(4.0.20)에서 문장 단위로 재면 정수 더하기 2.75 µs, 소수 더하기 2.85 µs로 거의 같다**(`_work/tips/result.json`, 2026-11-07). 블록 실행 고정비가 차이를 덮으므로 순정에서는 정수화보다 연산 수를 줄이는 쪽이 효과가 크다. 정수화는 tessvm에서 크게 이득(04쪽). 예: 좌표를 ×10000 정수로 들고, 곱한 뒤 `몫(곱, 10000)` 으로 되돌리기 (`몫`은 네이티브). 단 2^53(≈9e15)을 넘지 않게. (실측 3.1절)
6. **핫 루프의 임시값은 함수 지역 변수에.** 조회가 `getFunction`(O(1)) + 짧은 탐색이고 화면 갱신·렌더 요청이 없다. 단 함수 호출마다 지역 변수 배열 `_cloneDeep` 이 있으니 지역 변수는 필요한 만큼만. (`class/function.js:180-194`, `block_func.js:390`)
7. **전역 변수는 숨긴다** (텍스트 래스터화·도형 재그리기 제거). 그래도 `setValue` 마다 throttle 타이머와 무대 2회 렌더 요청은 남으므로, 루프 안에서 같은 변수를 반복해서 정하지 말고 함수 지역 변수에서 계산 후 마지막에 한 번만 정한다. (`variable.js:184-237, 338-343, 10`)
8. **변수·리스트 총개수를 줄이고, 자주 쓰는 것을 먼저 만든다.** 모든 변수 블록이 매번 전체 배열을 선형 탐색한다 (V=1000이면 조회 1회 ~1.75 µs). 쓰지 않는 변수·지역 변수를 정리할 것. 클론의 지역 변수는 탐색 2회. (`variable_container.js:1353-1375`)
9. **리스트 5000개 한도를 설계에 넣는다.** 넘치면 앞 항목이 조용히 버려지고 매번 배열 복사 + 토스트. 큰 가중치는 여러 리스트로 나누거나 항목 하나에 여러 수를 담는다(꺼낼 때 문자열 블록 비용이 생기므로 블록 수와 저울질). 큰 수는 문자열 자릿수보다 **리스트에 큰 기수(10^6~10^7) 덩어리**로. (`listVariable.js:6-15, 29-40`)
10. **리스트 접근은 O(1) 블록 위주로**: n번째 항목·바꾸기·추가·항목 수는 O(1). `포함`은 O(n)+원소마다 `toString`, 앞쪽 `넣기/삭제`는 O(n). 스택은 끝에서 추가·삭제(`삭제` 인덱스에 **0** 을 주면 마지막 항목 삭제 = O(1)). (`block_variable.js:1096-1102`, `listVariable.js:257-260`)
11. **무작위 실수는 쓰지 말고 정수 무작위 후 스케일.** 실수 무작위는 0.01 단위 문자열이다. (`block_calc.js:301-302`)
12. **나눗셈 결과가 아주 작을 수 있으면(1e-5 미만) 정밀도를 의심.** 20자리 반올림 때문에 유효숫자가 줄고 5e-21 미만은 0. 역수를 곱하는 형태로 바꾸면 곱셈은 이 제한이 없다. (BigNumber `DECIMAL_PLACES=20`)
13. **조건식의 부작용·예외는 중첩 `만약`으로.** `그리고/또는`은 양쪽을 항상 계산하고, 리스트 범위 밖·`char_at` 범위 밖·`asin(>1)` 은 작품 전체를 멈춘다. (`scope.js:187-209`, `executors.js:50-66`, `util/utils.js:2160-2172`)
14. **숫자 데이터는 숫자로 저장한다.** 문자열 숫자는 비교 때마다 `Number()`, 계산 때마다 `parseFloat` 를 거친다(각각은 수십 ns로 작지만 루프에선 누적). 특히 `".5"` 처럼 정규식에 안 걸리는 문자열은 `+` 에서 **이어붙이기**가 된다. (`util/utils.js:470-479`, `block_calc.js:160-173`)
15. **`log` 로 자릿수를 세지 말 것** (log(1000)=2.9999999999999996). 큰 수 자릿수는 `length_of_string` 이나 비교로. (`block_calc.js:783-785`)
16. **계산 루프에 공유/실시간 변수·리스트를 쓰지 않는다** — 블록마다 Promise 로 스레드가 1틱 이상 멈춘다. (`block_variable.js:981-993`, `variable.js:344-363`)
17. **큰 지역 리스트를 가진 오브젝트의 클론을 많이 만들지 않는다** — 클론 1개마다 그 리스트를 JSON 깊은 복사. 큰 데이터는 전역 리스트에. (`class/object.js:661-669`, `listVariable.js:527`)
18. **순정에서는 옛 네이티브 사칙연산 블록** `calc_plus/minus/times/divide` 를 JSON으로 넣는다. 2번 규칙의 비용 대부분이 사라진다(OBJ 렌더러에서 실측, 3.7절). 대신 BigNumber 의 `0.1+0.2=0.3` 보정은 없어진다. tessvm에서는 속도 차이 없음.
