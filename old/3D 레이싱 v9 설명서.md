# 3D 레이싱 v9 — 설명서

`3D 레이싱 v9.ent` 는 v8에서 **메인 메뉴를 카테고리로 묶고**, **실시간 변수 저장의 동시 접속 처리를 보강한** 버전입니다.
게임 내용·조작·규칙은 v8과 같습니다(v8 설명서는 `old/`에, 처음이라면 `3D 레이싱 소개.md`).

## 1. 메인 메뉴 — 카테고리로 묶음

13줄이던 메뉴를 6줄로 줄였습니다. ▶ 표시가 있는 줄은 ENTER로 들어가는 묶음입니다.

```
RACE START
RACE SETUP    ▶  MODE / RULES / CIRCUIT / AI LEVEL / LAPS(GHOST·ASSIST) / WEATHER / RACE START / BACK
CAR & GARAGE  ▶  CAR / GARAGE / BACK
PROFILE
SETTINGS      ▶  GRAPHICS / SOUND / BACK
TRACK EDITOR
```

- 묶음 줄에는 요약이 보입니다: RACE SETUP은 서킷(챔피언십이면 CHAMPIONSHIP), CAR & GARAGE는 차 이름(쓸 포인트가 있으면 함께),
  SETTINGS는 그래픽과 소리. 오른쪽 카드도 그 묶음의 요약 카드가 나옵니다.
- 안으로 들어가면 제목 아래에 `MAIN MENU > RACE SETUP` 처럼 위치가 표시됩니다.
- **BACK** 줄이나 **ESC**로 위로 돌아갑니다. RACE SETUP 안에도 RACE START가 있어서 설정을 마치고 바로 출발할 수 있습니다.
- 차 쇼룸·차고·서킷 화면에서 돌아오면 들어갔던 묶음 안으로 돌아옵니다.

## 2. 실시간 변수 저장 — 동시에 쓸 때

엔트리의 실시간 변수는 **마지막에 도착한 쓰기가 이기는**(last-write-wins) 방식이고, "내가 읽은 값이 그대로일 때만 쓰기" 같은
기능이 없습니다. 그래서 두 사람이 거의 동시에 같은 변수에 쓰면 먼저 도착한 쪽이 덮어써집니다.
v8(이후 수정)부터 이것을 고려해서, 게임은 쓰기를 믿지 않고 **확인하고 다시 쓰는** 방식으로 저장합니다.

1. **칸 나누기** — 저장은 닉네임에 따라 16개 변수(`RT_S1`~`RT_S16`)로 나뉩니다. 같은 칸을 쓰는 사람끼리만 부딪힙니다.
2. **읽고 → 합치고 → 쓰기** — 쓰기 직전에 그 칸을 다시 읽고, 서버에 있는 내 줄과 합친 뒤(경험치·통계는 큰 값, 기록은 빠른 값,
   도전과제는 모두) **내 줄만 바꾸고 다른 사람 줄은 그대로 둔 채** 씁니다.
3. **확인** — 쓰고 2초 뒤 다시 읽어 봅니다. 다른 사람이 내 쓰기보다 먼저 읽은 값으로 덮어써서 내 줄이 없거나 옛 것이면
4. **재시도** — 무작위로, 점점 길게 기다렸다가(0.2–1.6초 × 시도 횟수, 최대 6배) 1–3을 다시 합니다.
   덮어쓴 사람의 기록도 칸에 남아 있으므로, 결국 두 사람 기록이 모두 남습니다.
5. **랭킹**(`RT_K`)도 같은 방식입니다: 등록 → 2초 뒤 확인 → 내 이름·시간이 없으면 재시도.

### v9에서 더 막은 구멍 2가지
- **기록 확인을 "경험치 비교"에서 "내 줄 전체 비교"로** — v8은 서버에 있는 내 경험치가 저장한 값 이상이면 성공으로 봤습니다.
  그래서 경험치가 안 바뀌는 변경(차고 업그레이드·세팅)을 다른 사람이 옛 줄로 덮으면 모르고 지나갈 수 있었습니다.
  이제는 내가 쓴 줄이 글자 그대로 있어야 성공입니다.
- **세계 기록 고스트가 1위의 것인지 확인** — 두 사람이 거의 동시에 새 1위 랩을 세우면, 랭킹은 재시도로 맞춰져도
  고스트 변수(`RT_G`)에는 **2위가 된 사람의 고스트**가 남을 수 있었습니다(네트워크 지연이 들쭉날쭉한 모델에서 20번 중 10번).
  이제 1위는 확인 단계에서 고스트의 이름·시간이 자기 것인지 보고 아니면 다시 올리고, 고스트를 불러올 때도 랭킹 1위와
  이름·시간이 맞는 것만 세계 기록으로 씁니다. 같은 시험에서 20번 중 0번.

### 시험 (`_work/racing/t7/multi.mjs`, 엔트리 실시간 변수 서버를 흉내 낸 모델)
| 시험 | 내용 | 결과 |
|---|---|---|
| A | 저장이 늦게 도착한 사람 | 통과 |
| B | 같은 칸에 두 명이 같은 순간 저장 ×10 | 잃은 기록 0 |
| C | 세 명이 같은 서킷 랭킹에 같은 순간 등록 | 3명 모두 남음 |
| D | 랭킹이 도착하기 전에 세운 랩 | 통과 |
| E | 4명이 한 칸에서 60초 동안 무작위 저장·랩 | 4/4 저장, 랭킹 모두 반영 |
| F (v9) | 경험치 없는 차고 변경 vs 같은 순간 저장 ×6 | 잃은 변경 0 |
| G (v9) | 두 명이 같은 순간 새 1위, 지연 0–300 ms 무작위 ×20 | 잘못된 고스트 0 (v8: 10) |

### 남는 한계
- 같은 사람이 **두 기기에서 동시에** 플레이하면 경험치는 합쳐지지 않고 큰 쪽이 남습니다.
- 한 칸(2400자, 약 25명)이 가득 차면 가장 오래 저장하지 않은 사람의 줄부터 지웁니다. 한 칸에 25명 넘게 **동시에 계속**
  저장하면 서로 밀어내며 재시도가 이어질 수 있습니다.
- 실제 playentry 서버에서 여러 명이 동시에 시험하지는 못했습니다(서버 동작은 엔트리 소스를 보고 만든 모델로 시험).
- tessvm 확장 0.3.9에서는 실시간 변수 쓰기가 서버에 전달되지 않는 버그 때문에 저장하지 않습니다(읽기만, v8과 같음).
