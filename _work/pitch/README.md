# 목소리 높이 바꾸기 (말 빠르기는 그대로)

결과물: 저장소 루트의 `목소리 높이 바꾸기.ent`

## 원리
엔트리의 소리 속도(0.5–2배)는 음높이와 빠르기를 같이 바꾼다. 빠르기를 지키려고 목소리를
80 ms 조각(1/30 s마다 하나, Hann 페이드)으로 잘라 한 파일에 늘어놓는다. 조각마다 앞뒤 40 ms 무음이 붙어
한 칸이 160 ms다(`목소리 조각` 소리). 작품은 매 프레임(60 fps) 지금 재생 위치의 조각을
"소리 ( )초부터 ( )초까지 재생하기"로 튼다. 속도 r에서 조각은 r배 높고 1/r배 짧게 나오고,
새 조각이 매 프레임 시작되니 위치는 보통 빠르기로 나아간다.

- 순정 엔트리는 구간 재생을 **실제 시간**으로 끊는다(SoundJS setTimeout). 그래서 r < 1이면 구간을 160/r ms로 요청한다.
  tessvm은 파일 시간으로 끊으므로 `$TESSVM == 1`이면 160 ms 그대로 요청한다.
- 조각 앞뒤 무음은 MP3 디코더 지연과 늦은 정지를 흡수한다(크롬은 ffmpeg MP3 지연 0 측정).
- 음량: 느리게 틀수록 조각이 많이 겹쳐 커진다. 녹음에 맞춘 곡선은 r < 1이면 12 + 48r %, 아니면 44 + 19r %다.

## 파일
- `build.mjs [voice.wav] [out.ent]`: 목소리 다듬기 → 조각 파일 → MP3(ffmpeg) → 블록 → .ent
- `sim.mjs`: 오프라인 모형(조각 길이 고르기, 음높이 측정)
- `etest.mjs`: 오프라인 편집기(entry-vibe-coding `node server.js`)에서 실행하며 실제 출력을 녹음하고 측정한다.
  편집기가 작품 소리를 등록하지 않아 테스트가 직접 등록한다.
- `ttest.mjs`: tessvm(`_work/tessvm` `node tsrv.mjs`)에서 같은 측정을 한다.
- `voice.wav`: Windows TTS(Heami) 샘플 문장

## 조각 만들기 (파일 넣으면 조각 MP3 + .ent)
저장소 루트의 `조각 만들기.html`을 더블클릭해 브라우저로 연다(인터넷 필요: lamejs를 cdnjs에서 받음).
공개 버전: https://claude.ai/artifact/5mQHcK47Bf8nUXtaqqKwCg (그 화면은 .zip으로만 받을 수 있다: downloads 기능 허용 목록)

- 브라우저 안에서 전부 처리한다: 디코드 → 44.1 kHz 모노 → 앞뒤 −45 dB 무음 자르기, 최고 0.9, 앞뒤 50 ms → 조각 → lamejs 64 kbps
  → 파형 PNG → `template.json`의 작품에 소리·그림·변수(`목소리길이`, `마지막조각`)를 바꿔 넣고 tar.gz(.ent).
- lamejs MP3는 갭리스 헤더가 없어 크롬 디코드 때 앞에 1101샘플(25 ms)이 붙는다 → 인코딩 전에 그만큼 잘라 낸다(`LAME_DELAY`).
- 작품은 이제 목소리마다 다른 숫자를 변수 `목소리길이`, `마지막조각`에서 읽는다(build.mjs가 template.json도 쓴다).
- 다시 만들기: `node build.mjs` → `node gen-page.mjs 1101`. 시험: `node ptest.mjs [파일]`(페이지가 만든 .ent를
  from-page.ent로 저장) → `node etest.mjs from-page.ent`(`SHORT=1`이면 두 음높이만), `node ttest.mjs from-page.ent`.
- 측정: 샘플 처리 0.7 s. 영어 5.5 s 음성: 엔트리에서 길이 5.30/5.34/5.38 s(원본/+4/−12), 음높이 ×1.27, ×0.52.
