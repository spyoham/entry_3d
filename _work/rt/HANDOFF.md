## tessvm에서 알아낸 것 (속도에 큰 것부터)
1. **틱 몰아 실행**: 60틱/초 고정 스텝. 틱이 16.7ms를 넘으면 한 화면에 최대 4틱을 실행한다. 틱 29ms면 34틱/초로 재어지지만 화면은 9번/초. `tm.mjs`의 `ticks/s`만 보면 속는다. 작품 안에서는 `dateSec`로 1초의 틱 수를 세어 57 미만이면 과부하로 본다(프로젝트 타이머는 틱마다 1/60초씩만 간다).
2. **색별 묶음 그리기**: 같은 스타일의 2점 획이 16개 이상 이어지면 메시 하나(`render/segments.js`). 색을 줄 조각마다 바꾸면 8000조각에 그리기 15ms, 색별로 모으면 1.3ms. 획은 `goto, penDown, goto, penUp`.
3. **숫자 상수는 글자**: 블록의 숫자는 `"5"`로 컴파일된다. 변수·리스트에 넣으면 글자로 남아 쓸 때마다 `parseFloat`. `ejs.mjs`를 고쳐 함수 안의 숫자 상수를 진입 때 `(5 - 0)`으로 만든 지역 변수에서 읽게 했다(대입, 비교, 리스트 번호, 호출 인자). `x + 3`은 `x - (-3)`으로(PLUS는 글자 여부를 먼저 본다). 틱 23 → 19ms.
4. **소수는 느리다**: `+ − ×`에 소수가 섞이면 `snap`(자릿수 세기). 나눗셈은 `idiv`, 제곱근은 `idiv(sqrt, 1)`로 바로 정수로.
5. **함수 호출**: 호출 자체는 0.12µs지만 지역 변수 하나에 약 10ns(시작 때 모두 `"0"`으로 채움). 지역 150개면 1.5µs.
6. **큰 함수는 느리다**: 같은 반복이 작은 함수에서는 연산당 2.7ns, `traceCluster` 크기에서는 약 8ns. 드문 경로를 함수로 빼도(`mirrorCell`, `floorShade`) 이득이 없었다 — 호출 비용과 비슷했다. `a + b`를 `a - (0 - b)`로 바꾸는 것(`FASTPLUS=1`)은 더 느렸다.
7. Chrome 154는 같은 코드가 Node 24보다 약 25% 느리다. 헤드리스는 25초쯤 뒤 2배 느려질 때가 있다(창을 띄우면 없음).

## 렌더러 구조
- 카메라 공간에서 추적. 줄마다: 구의 구간(2차식) + 삼각형 구간(투영 변) → 겹침 묶음 → 덮는 물체가 바뀌는 곳에서 나눔 → 각 조각을 간격 격자로 추적.
- 조각 안: 이웃 광선의 "만난 것 표시"(ssig)가 같으면 사이를 중간에서 색 바꿈, 다르면 이분.
- 줄 순서는 `ROWSEQ`: 핵심 줄(2줄 간격)과 그 사이 줄. 사이 줄은 위아래 핵심 줄의 표시가 같으면 색을 가져다 씀(`CS`, `CC`, 프레임·줄 도장 포함).
- 배경: `rowPrep`이 바닥(타일 DDA, 그림자 구간)·하늘(띠 경계)을 `BGX/BGV`로, `bgSeg`가 칠함.
- 조각 저장소 둘(`sBase` 0 / `PALN`): 인터레이스에서 홀수 줄 조각을 한 틱 보관했다가 짝수 줄과 같은 틱에 그림. 펜 B는 `timer() != bTick`으로 "다음 틱"을 안다(두 오브젝트의 실행 순서와 무관).
- 삼각형: 정적 표는 빌드 때. 프레임마다 꼭짓점 변환, 근평면 자르기, BVH 상자 다시 맞추기(`meshSetup`). `bvhHit`는 스택 없이 `BSKIP`을 따라감.

## 수치 (이 PC, 창 띄운 Chrome 154, 시작 화면)

- 간격을 넓히고 표본 사이를 선형 보간(지금은 중간에서 한 번 바꿈)

# v1.alpha (2026-10-05)

요청: "딜레이 제거 코드와 ~인 동안 반복하기 코드를 제거해서 1.alpha 버전을 만들어줘"
산출물: 루트 `엔트리 레이트레이서 v1.alpha.ent`, `엔트리 레이트레이서 v1.alpha 설명서.md`
빌드: `node build.mjs alpha.ent ALPHA=1` → `loops 83, whileBlocks 0, tricks 0, globals 419, functions 106`

- `deloop.mjs`: 매크로를 편 소스에서 `while`을 모두 자기 호출 함수로 바꾼다. 반복과 바깥이 함께 쓰는 지역 변수는 전역(`z함수_이름`)으로, 한 반복의 한 바퀴 안에서 "읽기 전에 반드시 쓰는" 변수는 그 반복함수의 지역으로 둔다(전부 전역이면 틱 44ms, 이렇게 하면 27~31ms; v1.0은 13~14ms). `break`는 표시 변수.
- 확인: `nrun.mjs`로 v1.0과 300틱 뒤 `nsamp, nrun, nused, bvCalls`가 같음. 알파 소스는 Node 시뮬레이터로는 못 돌린다(초기화 재귀 4만 단계가 JS 스택을 넘김).
- 상수 풀을 끄는 것(`POOL=0`)은 이득 없음.
- `src/main.js`에 AUTO 화면 건너뛰기(`skipN`, `drawStep`)를 넣었다. 지금 소스로 `ALPHA` 없이 빌드하면 이 기능이 든 판이 나오고, 루트의 v1.0 파일은 넣기 전 빌드 그대로다. v1.0을 다시 낼 때는 버전을 올릴 것.
