## 구조에서 알아 둘 것
- **쪽**: 모델 `NP`=16쪽 + 성긴 모델 2쪽(`NP+1`, `NP+2`). 쪽마다 리스트 16개(`VX VY VZ FA FB FC FE NA NB NC ND FM SX SY LK CL`). 파일 꼭짓점은 `NQ`=20쪽(`RX RY RZ RM RN WH`).
- 쪽 안 번호로 다시 매김: `RM`에 (도장 + 쪽 안 번호). 도장(`stampLo`)은 쪽이 바뀔 때마다 8192씩 커지므로 지난 쪽의 값은 저절로 무효. 같은 자리 꼭짓점은 `RM`이 음수(첫 꼭짓점의 번호).
- 리스트는 줄이지 않는다. 길이가 모자라면 push, 아니면 덮어쓰기(`M_put`, `putAll`). 한 묶음의 리스트는 길이가 늘 같다는 것에 기대므로 **묶음의 리스트는 꼭 함께 쓸 것**.
- 함수의 지역 변수는 `''`을 0으로 읽는다(`value || 0`). 그래서 낱말 버퍼 `w`는 비지 않게 했다(끝에 `# #`, 빈 문자열 대신 `' '`/`'#'`).
- 깊이 사슬: `HD[칸]` 머리, `LK쪽[면]` 다음. 값은 쪽 하나면 면 번호, 여러 쪽이면 `쪽*8192 + 면`. 칠하면서 머리를 0으로 되돌리고, 도중에 그만둔 그림이 있으면(`hdDirty`) 다음에 통째로 비운다.
- 순정의 펜 층: 시작할 때 `penColorHex`를 먼저 불러 펜 층을 채우기 층보다 먼저 만든다(먼저 만든 층이 아래). 배경은 펜 층의 두꺼운 선.
- 작품 안에 모델이 든 채 시작(`nLv > 0`): 페이지가 변수·리스트를 채워 넣은 것. 시작 때 `pageOp(p, 6)`으로 작업 리스트만 만든다. 페이지는 `RX… WH`, 작업 리스트, 성긴 모델 임시 리스트를 비우고 `wPages = 0`으로 둔다.

## 엔진에서 알아낸 것
- **옛 사칙연산 블록**(`calc_plus/minus/times/divide`, 피연산자 0·2번): 엔트리에 남아 있고 BigNumber를 안 거침. tessvm은 `calc_basic`과 같은 코드로 컴파일("10여 년 전 이름"). 꼭짓점 변환 43 → 31 µs(작은 시험), 매듭 한 장 122 → 108 ms. `LEGACY=0`으로 끌 수 있음.
- **리스트 찾기는 선형**: `_.find(lists_, {id_})`. 리스트 하나 지날 때 약 8 ns(300번째 리스트는 +2.4 µs). → `listOrder`.
- **지역 변수 찾기도 선형**(`_.find(localVariables, fn)`), 전역 변수 정하기는 약 5 µs. 프로파일은 해석기(Scope.run, execute) 37%+, 변수 찾기 약 25%.
- 블록 하나 약 0.5~0.8 µs(값 블록), 문장은 그 서너 배. 문장 수를 줄이려 임시 변수를 없애도 거의 그대로였다(변환 8문장 → 4문장: 43.9 → 43.1 µs). **블록 수**가 값이다.
- 블록의 기본값 필드(x, y, movable, deletable, …)는 없어도 두 엔진이 같게 읽는다. project.json 9.5 → 3.6 MB.
- `set_fill_color`와 `start_fill`은 새 도형을 시작하고 `locate_xy`는 `paint.stop`이 아닐 때 점을 더한다. `fillStop, goto, fillColorHex, fillStart, goto, goto` 6문장과 뾰족이를 남기는 5문장 방식은 시간이 같았다(14.6 µs).
- 순정의 실선(도형 사이 틈)은 배경이 **채우기 층**에 있으면 펜 테두리로도 안 없어진다(배경이 펜 선을 가림).
- 입력창 붙여넣기(Chromium): 줄바꿈(CR LF 포함)이 공백 하나로, 탭은 그대로. 7.8 MB도 1.2초. 순정의 입력창은 숨은 `input`이라 `Entry.stage.inputField.focus()` 뒤 Ctrl+V.
- tessvm 초시계는 틱 × 1/60초(첫 틱은 0). 12프레임 중 9번 이상 1/60의 배수면 tessvm(`probe`).
- tessvm은 펜·채우기 층 순서를 엔트리처럼 "처음 쓴 순서"로 둔다.
- 엔트리의 `==`는 숫자 모양 글자를 숫자로 본다(`'1.0' == '1'`). 꼭짓점 같은 자리 비교가 이것에 기댄다.

## 최적화가 온 길 (순정, 매듭 한 장)
207 ms(삼각형 2304) → 152(사슬 칸 1/4·칠하며 비우기·옛 블록·임시 변수 줄임) → 107(사각형 면 그대로). 스포츠카 50 → 31 ms(꼭짓점 합치기 + 닫힌 겉면; 큰 면 방식이 든 값).
- 해 봤는데 효과 없던 것: 문장 수 줄이기, 반복 2배 펼침(43.1 → 43.4), 숫자 상수를 지역 변수에 모으지 않기(`PLAIN=1`: 그리기는 같고 읽기만 7% 빠름 → 끔).
- 읽기는 낱말당 블록 135개쯤. `COUNT`로 본 큰 줄: 버퍼 자르기, 해시 사슬, 쪽 고르는 if 나무. 첫 쪽만 따로 빼기(`tree1`)와 묶음 쓰기(`putAll`)로 7% 줄였을 뿐이다. → 큰 모델은 페이지로.

## 큰 면 (바닥·벽)
- 면의 깊이를 가운데로 잡으면 바닥의 먼 쪽 절반 위에 선 물체가 바닥보다 먼저 칠해져 덮인다.
- 모델에 큰 면(모델 폭의 1/5 넘는 것, `BIGL`)이 하나라도 있으면(`PBG`, `LVG`, `rBig`) 면마다 가장 먼 점이나 가장 가까운 점을 쓴다. 눈과 모델 가운데가 면의 평면에서 같은 쪽이면 먼 점(바닥, 방의 안쪽 벽), 평면이 둘을 가르면 가까운 점(밖에서 본 앞벽·지붕). 판정은 `ND`의 부호 하나.
- 값: 면 살피기 31 → 42 µs(앞면만), 49 → 66 µs(양면). 그래서 큰 면이 없는 모델은 예전 방식.
- 방 모델은 "양면"(자동)이면 밖에서 본 상자, 단추로 "앞면만"이면 안이 들여다보인다.

## 안 한 것 / 다음 후보
- playentry 실서버에서 실행·올리기 확인. Chrome 외 브라우저 붙여넣기.
- 읽기 가속: 줄 단위가 아니라 `v`/`f` 뒤 낱말을 바로 잘라 내는 방식(낱말당 문장 17 → 6쯤), 같은 자리 합치기를 쪽 안에서 따로(나무 없이).
- 성긴 모델: 격자 묶기라 가는 부분이 끊긴다. 페이지 쪽에서 더 나은 단순화(quadric)를 해서 넣어 주는 길이 있다.
- 꼭짓점 색(`v x y z r g b`), 선(`l`)·점(`p`), 부드러운 음영.
- 카메라를 모델 안으로(가까운 면 자르기 필요).
- 순정에서 쪽이 뒤인 리스트가 느린 것(리스트 순서를 그때그때 바꿀 수는 없음).

## 속도 맞추기에서 알아 둘 것
- `cap`(움직일 때 한 프레임의 일)과 `capR`(멈춘 뒤 나눠 그릴 때)은 따로 잰다. 한데 재면 멈춘 뒤의 느린 프레임(펜 테두리, 쌓인 그림 다시 그리기)이 `cap`을 깎아 움직일 때 필요 이상 성긴 단계가 골라졌다.
- 순정의 목표: 움직일 때 초당 12장(`tg`), 멈춘 뒤 칠할 때 초당 5장. 순정은 프레임마다 그때까지의 획을 모두 다시 그리므로 잘게 나누면 손해다(방 장면 12초 → 5초).
- tessvm의 목표는 72(틱이 60을 채우도록 여유). 60을 채운 초에는 3배씩 늘리고, 못 채운 초에 잰 값의 1.15배(`capFail`)를 30초 동안 천장으로 둔다. 단계는 직전보다 고운 쪽으로 갈 때만 여유 20%를 요구한다(`pickWas`).
